# 历史查询基准（2026-10-15，Windows）

本次离线合成负载证明：列表不必先审计全部模型输入和遍历全部快照。1000 个实验时，首页最近记录观测中位数从 14039ms 降至 1875ms，第一页从 16358ms 降至 2209ms。它不是生产负载或受控硬件性能承诺；后台还有开发门禁，空间遍历观测明显波动，不能将所有时间差都归因于代码。

## 数据与方法

Windows x64、Node v24.11.1；相同本地磁盘、相同合成文件，先前版本来自集成基线 `ded66e69a7b6149f7912d8880a6ea97b0c1b24c6` 的独立编译产物。改后包含 P09a 集成基线 `8b777c79f6c393389384fef472b466858f73fed0` 和本批列表实现。原始逐次读数见[测量数据](history-query-benchmark-data.json)。

生成 1000 个真实离线 Fake Runtime 实验，各两个 run，各四次真实 Host generation 输入审计快照（16KiB 正文及 1×1 PNG 引用），每个 run 额外十二个 4KiB 快照文件。10/100 个样本是相同数据的实际文件子集，不使用 junction 代替目录。实验共享一个小型 legacy case，不覆盖大规模 v2 冻结附件校验。`compare: false`，没有正式 owned HTML 报告；结果不能外推大量报告 hash 或复杂图片负载。

每项五次，每次独立 Node 进程，共享操作系统文件缓存；没有强行驱逐缓存，不能称为冷盘测试。计时从模块载入后开始。`readFile` 是调用次数，包含失败尝试；字节数是成功返回的逻辑字节，不是物理磁盘 I/O。`readdir`/`lstat` 为 API 调用数，不计 SDK 和 Node 内部读取；流式文件 hash 不在此计数器内。内存记录独立进程 maxRSS，包含模块载入，另保留 5ms 采样 RSS，不能将采样称为精确内存峰值。

原详情仅读取事件；原列表此前已经审计全部实验。改后列表延后审计，详情测量实际执行 `readLocalHistoryExperiment` 加事件读取，故详情增加十几毫秒是转移到选择时的工作，不能只比较原单次事件读取。独立空间遍历是同一参考遍历器，两侧调用量完全一致；后台负载未受控，无法把更慢的观测归因为某个因素，本批不宣称空间统计算法加速。

1000 个实验的最近记录查询：`readFile` 从 32001 降至 7001，逻辑返回字节从 296247153 降至 150752404；`readdir` 从 77008 降至 1002，`lstat` 从 214007 降至 4。列表不读取模型正文/图片附件、不进入快照目录，由自动化逆例另行证明。该项中位时间对应进程 maxRSS 从约 1215MiB 降至 155MiB；不同项对应不同进程，不能把该数值当作整机内存。

## 可复现命令与限制

仅用于开发构建，包含 `dist/test` 的 fake Runtime，不发真实模型请求。生成器要求专用空目录，拒绝覆盖已有目录；不会清理旧数据。临时根使用工作区外短路径。

```powershell
npm run build
node scripts/history-query-benchmark.mjs generate C:/reprise-history-benchmark
node scripts/history-query-benchmark.mjs measure C:/reprise-history-benchmark measurements.json
```

`REPRISE_BENCH_DIST` 可指定已经保存的基准编译目录，两侧必须使用同一数据目录和同一计量脚本。测量不设置时延门禁；报告数字只是本次样本。空间统计独立执行，列表仍读取每个实验日志并线性排序，因此 1000 个实验仍有约两秒开销。此次收益足以支持职责分离，不足以证明需要数据库或持久化索引；后续只有实测需求再引入可重建索引。
