# 验证一次改动

适用：在本地确认改动可交付，不调用真实计费 Runtime。

1. 先标明当前修复或目标迁移，并找出对应规范。非平凡任务用[任务简报模板](../plan/task-brief-template.md)写清输入、期望退出码或快照及回滚条件；本指南不是模板替代品。
2. 对照[日常开发命令表](../development.md#验证命令)选检查：文档只跑文档门禁；代码先做受影响测试的窄回归，收尾跑代码门禁。测试读取 `dist/`，改源码后必须先构建。
3. 检查失败时保存完整命令、退出码、Node/OS 与最小复现，修复后重跑；不降低阈值或把红灯解释成通过。新增或修改门禁须带[反向用例](../engineering-gates.md#门禁必须能失败)。
4. 审阅 diff、日志与附件，移除秘密和私有输入；写下实际通过项、未跑原因与剩余风险。模拟测试不能证明真实 Runtime 或所有平台可用。

完成条件：所选检查满足任务验收，失败与未验证项如实记录；PR 按[贡献指南](../CONTRIBUTING.md)提供证据。真实 smoke 不是默认补充步骤，必须另行满足[准入程序](../codex-smoke-gate.md)。
