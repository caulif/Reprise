# 新增或更新 ADR

适用：需要记录会长期约束实现的选择，而不是记一次工作流水账。

1. 按 [ADR 指南](../decisions/README.md)用主题、协议名或受影响路径检索相关记录，阅读命中记录及其替代链接；不用通读或维护全局索引。
2. 对照指南的触发条件与豁免。需要 ADR 就在同一次变更中新增或更新；不需要则在任务或 PR 中写明无契约变化等具体理由，不造一份空 ADR。
3. 按[决策记录格式](../documentation-structure.md#决策记录)选择目录、日期与状态，填写问题、决定、真实备选方案、影响和可观察验证条件。设计已确认但尚未生效的目标不能当作当前规则。
4. 替代旧决定时建立双向替代关系，不将旧理由改写成相反结论；局部迁移说明仍有效范围。当前行为同步产品/架构的唯一归宿，不在 ADR 复制整份规范。
5. 按[日常开发](../development.md#验证命令)验证本次改动；纯文档运行 `npm run verify:docs`，再人工检查弃案是否真实、状态与生效条件是否一致。

完成条件：相关 ADR 或豁免理由可从任务/PR 找到，链接与模板检查通过，验证条件能被复核。非平凡任务仍使用[任务简报模板](../plan/task-brief-template.md)，ADR 不代替施工验收。
