# Git Recovery 轻量化与 Codex 工具语义对齐规划

日期：2026-10-12。状态：首批已实施，后续方案待验证。按用户指定目录保存于 `docs/.locl/`。

Reprise 核对基线：`90f6a30b472d1a13d882d42c6f9e360ea703fae5`，当前 PR #117 分支。Codex 参考基线：`openai/codex@ddb33e34b278ca1b7d16d1e68f8ad363a2042f2e`。下文将当前事实、建议方案和待验证效果分开描述。

实施记录：本批实现显式 `gitStart` 程序接口、受管进程工具、失败与收尾传播、脱敏日志 artifact、安全读取并行和默认不构建的恢复提示。实际行为及限制以 [Recovery 架构](../architecture/recovery.md) 和 [决策记录](../decisions/accepted/2026-10-12-lightweight-recovery-and-managed-processes.md) 为准；以下保留实施前规划。缓存、PTY、宿主重启后的进程重连、大型仓库复制优化及 TUI 起点选择界面未在本批实现。尚未复跑计费模型或四项真实历史任务，不能从离线回归推断它们已稳定成功。

## 1. 建议先作出的决定

**把 Recovery 收敛为“恢复正确的任务起点”，把工具补成能持续运行、读取输出和可靠取消的通用工具。依赖与构建由实际执行需求触发。**

不增加新的 Agent 阶段，不引入另一套复杂审批或评分系统。明确可信起点时由 Provider 确定性恢复；不明确时才让 Agent 调查历史。已有写入审计、源目录保护、输入可复原和封存边界继续承担基础正确性保障。

优先顺序：

1. 明确恢复成功的含义，取消默认安装依赖与完整构建倾向。
2. 打通受管进程会话，分开“本次等待时间”和“命令生命期”。
3. 修正工具失败的传播和进程收尾，避免已不可恢复却继续消耗时间。
4. 对安全的独立读取开放并行；后台写进程必须持续占有工作区写权限。
5. 有测量依据后再优化依赖缓存、文件复制和跨任务资源竞争。

总运行预算继续采用 30 分钟，不另设任意模型请求次数上限。输出分页、内存保护和进程资源保护属于运行安全边界，不应被包装成限制模型调查次数的额度。

## 2. 当前方案与已观察的问题

### 2.1 当前调用链

```text
历史会话 / 源工作区
  → Provider 建立 staging、副本与源指纹保护
  → Recovery Agent：understand → restore → conclude
  → 机械校验、可选 readiness 命令、任务前 Git 边界校验
  → 接受 staging 为 baseline
  → Candidate 从 baseline 获得隔离副本
```

相关实现：

| 所有者 | 当前职责及本轮关注点 |
|---|---|
| [LocalWorkspaceProvider](../../src/environment/local-workspace-provider.ts) | `beginRecovery` 建立副本；`validateRecovery` 校验并封存；`acceptRecovery` 接受；`prepareRun` 复制候选工作区 |
| [文件复制](../../src/environment/local-workspace-fs.ts) | `copyTree` 逐文件复制；不是独立依赖缓存系统，不能假设自动排除所有依赖目录 |
| [Recovery Agent](../../src/agents/recovery-agent.ts) | 当前提示允许安装依赖、构建和运行验证，容易把恢复起点扩大成准备完整开发环境 |
| [Codex Recovery Pack](../../src/products/packs/codex/recovery/SKILL.md) | 提供历史解释与恢复指导；已有避免无必要完整构建的建议，但缺少明确默认策略 |
| [Recovery 工具](../../src/infrastructure/recovery-workspace-tools.ts) | `shell_exec` 仅暴露 command；默认执行超时 60 秒，无受管会话续读接口 |

因此，问题不宜简单归因于“系统强制 npm install”。实际损耗来自提示词允许的范围、工具能力和恢复成功语义共同作用。

### 2.2 最新测试证据

来源：本机 `docs/.local/recovery-proxy-retry-2026-10-12-2/report.md`（更换代理后的复测记录）。这是 Git 忽略的本地诊断依据；本文保留必要事实，不要求其他检出环境拥有该记录。

| 任务 | 实测终态 | 总耗时 | 模型请求数 |
|---|---|---:|---:|
| 单项鹈鹕 | ready，接受 | 3m31s | 29 |
| 并行鹈鹕 | ready，接受 | 3m12s | 24 |
| 并行 DOCX | ready，接受 | 9m16s | 62 |
| 路径识别 #1222 | 30 分钟取消，未接受 | 31m07s，含收尾 | 82 |
| Edit 自移动 #1451 | 工具失败，未接受 | 22m57s | 87 |

已确认：

- 本轮五次运行没有观察到 TLS handshake timeout；不能将最新 Git 失败继续归因于此前 TLS 问题。
- 两个 Git 任务一直停留在第一次 understand invocation，分别压缩 4 次和 5 次；请求多不等于完成阶段多。
- Edit 的同步 Rust 工具链安装命令约 60.609 秒超时；其后仍有约十分钟模型与工具工作，最终 invocation 才失败。
- 路径任务执行包含 `Start-Sleep -Seconds 90` 的命令，约 60.683 秒触发 shell 超时；后续继续安装和构建，最终因总时限取消。
- 失败后的 baseline HEAD 仍为历史结果，不是期望任务起点，不能交给 Candidate 当作成功恢复。
- 原始会话和源副本完整性检查通过；本轮没有证据显示污染了用户源目录。

待验证：模型为何在工具错误后继续工作，需要检查异步调用、错误汇聚与取消传播；不能仅凭十分钟间隔断言某一个内部函数必然吞错。最后一次模型等待也不能未经证据归因于 TLS 或依赖安装。

## 3. Codex 开源工具配置：复用什么

参考固定 SHA 的源码，而不是假设 Codex 桌面实际运行配置与开源默认值完全相同。

| Codex 已核对行为 | Reprise 建议 | 不直接照搬的部分 |
|---|---|---|
| `exec_command` 暴露工作目录、等待时间、输出预算，默认使用管道，可选 PTY | 补充受管进程启动与返回会话句柄 | 不直接要求 Windows PTY，也不复制全部权限审批参数 |
| `write_stdin` 用既有 `session_id` 写入或读取新增输出；空输入用于等待 | 实现同一进程会话续读，取代模型手写后台进程与 sleep 轮询 | 不以 OS PID 作为模型可操作的权限凭证 |
| 等待返回会话句柄与命令超时是不同语义；另有 one-shot 执行生命期 | 长任务返回 running，整体任务取消时终止；保留明确的同步兼容路径 | 不声称所有 Codex 执行模式都没有命令超时 |
| 工具注册取决于模型能力与功能配置 | 由 Runtime/工具适配器声明实际可用能力 | 不把注册不存在的工具名称写进 prompt |
| 并行支持显式声明；并行工具取得读锁，其他工具取得写锁 | 复用现有 executionMode，并增加后台进程生命期内的资源协调 | 不根据模型自称只读，就并行任意 shell 命令 |
| `apply_patch` 有专用 freeform 语法 | 首先保证现有 read/edit/write 清晰可用；确有收益时再增加补丁适配 | 不向只支持 JSON 工具的模型强塞 Codex freeform schema |
| 输出有截断和内部资源保护 | 分页返回增量输出，保留可定位的脱敏日志 | 不把输出截断误报为命令失败，也不把截断内容伪称完整证据 |

## 4. 目标流程：减少工作，而不是增加阶段

```text
任务目标 + 起点证据
  → 解析起点：已确认则直接恢复；未确认才调用 Agent 调查
  → Provider 物化隔离源码 + 明确的必要输入覆盖
  → 校验起点、输入和源目录完整性
  → baseline 可用
  → Candidate 编辑 → 按验证需求准备依赖 → 定向验证
```

这是现有 Recovery 内部职责收敛，不新增多 Agent 流水线。

### 4.1 起点分为“明确给定”和“历史推断”

- 用户或可信任务描述明确给定、可验证的 base commit：Provider 校验对象存在及仓库身份后直接物化。
- 历史会话里的 commit：只作为线索，须结合提交发生时机、历史 diff 和必要输入确认，不能见到一个 SHA 就 reset。
- 无法确认：Agent 调查并给出有证据的恢复方案；不静默接受历史结果 HEAD。
- commit 缺失：先检查已有对象和可用本地证据；确需 fetch 时走现有网络授权与审计，不默认拉取全部历史。

针对两项测试，验收时使用明确起点：

| 任务 | 起点 | 禁止混入的历史结果 |
|---|---|---|
| PI-Desktop #1222 | `110fc66751b4666b081ba86f146d60211ae717e9` | `85e69cba` 对应任务结果 |
| PI-Desktop #1451 | `278e929ca7065a51483cb3c7f293306adade1f9d` | `2ab74c33` 对应任务结果 |

### 4.2 源码起点不等于只有一个 commit

起点可能包含历史未提交修改、未跟踪输入、LFS 内容或子模块。必须明确哪些是原输入，哪些是历史成果，哪些只是可再生文件。

建议默认采用 Provider 自有的独立 Git 副本；从可信 base commit 恢复，再按记录应用必要输入覆盖。保留 Git 语义供 Candidate 使用，但不共享用户源目录的可写 Git 元数据。禁止直接对用户仓库 reset/clean，禁止盲目丢弃 dirty/untracked 输入。

Git archive、用户仓库直接 worktree、共享可变 alternates 都不作为第一版通用默认值：它们分别涉及 Git 元数据缺失、共享管理目录或对象生命周期问题。后续只有实测复制成为瓶颈时再单独评估。

历史答案不能通过任务工作区或工具挂载泄漏给 Candidate；审计存储与候选输入的可见范围继续分离。

### 4.3 成功条件收敛

Recovery 成功应证明：

1. 任务前源码/文件边界正确，必要输入存在，历史结果已按任务移除。
2. 原始源目录和会话未被修改。
3. staging 内没有仍能写入的后台进程，校验与封存之间不存在写入竞态。
4. baseline 满足现有路径、大小与持久化契约。

依赖未安装可以成功；如果用户明确要求恢复离线可运行环境，则按该目标准备并验证，不能统一跳过。报告分别说明“起点已验证”和“实际执行过哪些环境检查”，不增加另一套复杂状态机，不把未运行构建写成构建通过。

## 5. 通用工具改造

### 5.1 工具接口草案

以下为拟议接口语义，不是当前已存在的 schema，也不是要求复制 Codex 所有字段。

| 工具 | 必要输入 | 输出语义 |
|---|---|---|
| `exec_command` | cmd；可选 workdir、yield_time_ms、max_output_tokens | 立即完成返回 exit_code；尚未完成返回 session_id 与新增输出 |
| `write_stdin` | session_id；可选 chars、yield_time_ms、max_output_tokens | 等待同一进程或发送输入，返回增量输出及最新终态 |
| 进程终止接口 | 当前运行拥有的 session_id | 请求终止并等待进程树收尾；实现时决定独立 cancel 工具还是明确的会话操作 |
| 现有文件工具 | 延续受审计的 read/edit/write | 保持路径和写入日志边界，普通编辑冲突向模型返回可修复反馈 |

第一版以 Windows 管道执行为主。默认等待可参考 Codex 的 10 秒，但必须写进描述；等待结束表示返回控制权，不表示杀进程。长命令生命期由任务 deadline/取消管理。若保留显式命令 timeout，必须单独命名并明确超时会终止，不能与 yield 混用。

旧 `shell_exec` 保留兼容适配，避免让既有历史事件和 Runtime 失效；新 Agent 默认只暴露一套主要执行入口，减少同义工具选择负担。旧同步调用的错误结果必须真实，不能超时后返回成功。

### 5.2 会话所有权与封存

会话句柄绑定 experiment、Recovery/Candidate invocation 与工作区，不能跨运行使用。宿主重启后不得仅凭旧 PID 宣称进程仍受管；应记录会话失效并按恢复策略处理。

同一会话并发读取需要串行化消费或明确游标，避免输出丢失、重复或终态覆盖。每次返回 running/completed/failed/cancelled 的实际状态；普通非零退出码属于命令结果，不自动等同整个 Agent 无法继续。

结束 invocation、取消任务、接受 baseline 前，统一停止或等待所有拥有的写进程，完成输出与审计回调，再计算最终指纹。返回 session_id 不能释放后台进程占用的工作区写锁。

模型看到的命令、工作目录、输出片段、终态和截断标志必须能从事件恢复。长日志保存脱敏后的可定位副本；进入模型的分页引用同样有事件，不复制凭据或完整进程环境。

### 5.3 失败传播

| 情况 | 建议处理 |
|---|---|
| 命令非零退出、文件不存在、编辑 oldText 不匹配 | 返回可理解的结果，Agent 可以修正 |
| 单个命令显式超时 | 终止并收尾，返回实际超时；是否继续由任务策略决定 |
| 任务总时限或用户取消 | 停止新调用，取消模型/工具，收尾后结束任务 |
| 写入审计失败、持久化失败、源保护破坏、写入结果不确定 | 立即终止相关 invocation，禁止继续接受 baseline |
| 已失效或他人会话句柄 | 明确拒绝，不能降级为新命令或任意 PID 操作 |

重点检查 [工具 instrumentation](../../src/infrastructure/agent/tools.ts) 的错误包装、并行调用汇聚和取消传播。不能为“稳定成功”把 fatal 错误改成普通文本并继续运行。

### 5.4 并行范围

先开放有明确资源边界的 read/list/search 等独立读取。现有 [工具类型](../../src/infrastructure/agent/types.ts) 已有 executionMode，应扩展资源协调而不是另造调度器。

同一工作区的写入、安装、Git 状态变更默认串行。shell 可以执行任意代码，不能仅靠命令字符串或模型声明当作安全读取。后台命令仍在写时，读取也可能看到不一致状态，默认排他到进程结束。

四个独立任务仍可并行，但下载、磁盘、CPU 可能竞争。需要记录排队时间与执行时间后决定是否增加宿主级安装互斥，不承诺并发数越高越快。

## 6. 依赖策略：按需求准备，不转移浪费

### 6.1 默认不准备完整环境

Recovery 不执行根目录完整 build/test，不安装 latest/stable 工具链，不主动更新 lockfile。Candidate 开始时可以先阅读和修改源码，发现具体验证命令缺依赖再安装。

仅把安装从 Recovery 移到 Candidate，不保证总耗时减少。真实收益必须来自减少无关依赖、复用下载和缩小验证范围。

两项 Git 任务的历史 PI-Desktop 根 build 同时包含 JS workspace 构建和 Rust release 构建；因此不能用“运行根 build”充当通用轻量检查。Edit 任务只有两份 Rust 源文件和三份文档变更，也不能由此推断必需安装完整前端环境。

### 6.2 按需安装顺序

1. 读取项目 packageManager、engines、lockfile 和 toolchain 声明。
2. 选择与改动相关的最小有效测试；检查本机已有工具，避免重复准备。
3. 缺失时安装该测试所需依赖；使用锁定版本和项目支持的 frozen/locked 模式。
4. 若选择的验证仍需大型构建，明确执行原因与实际成本，不伪称已经轻量化。

本机 Node/pnpm/Rust 属于宿主能力，可单独配置一次；任务工具不得擅自更改全局默认工具链或用户配置。安装失败要保留原因，不能用另一个任意版本悄悄替代。

### 6.3 缓存分层

第一层优先包下载缓存，例如 pnpm store 和 Cargo 下载缓存；采用包管理器本身的锁与完整性机制。按来源、平台、运行时和版本隔离必要内容，处理缓存可写权限与污染问题。

第二层才考虑物化依赖和编译产物缓存，需要 lockfile、平台/架构、运行时 ABI、工具链、编译参数等缓存键，以及候选间写隔离。历史结果目录的 `node_modules`、`target`、`dist` 不直接当作可信基线。

不增加默认 Docker/容器镜像构建阶段。Windows 原生工具和现有 Provider 优先；容器只在确有项目兼容性或隔离收益时另行评估。

## 7. Prompt 调整方向

保持单个通用目标提示，输入优先给出：用户任务、交付目标、可读证据、明确起点和工具能力。不再把“安装并构建项目”作为恢复成功的默认暗示。

建议表达的核心约束只有：恢复任务开始前的输入；保留原输入且移除历史成果；无需安装依赖或构建，除非这是恢复目标本身；依据工具真实结果判断完成；遇到缺失起点或不可安全处理的输入时说明证据缺口。

这是方向性说明，不复制当前完整 prompt，也不为鹈鹕、DOCX、路径识别分别写业务规则。起点、文件完整性和预算由宿主负责；模型处理不确定历史和实际任务判断。

总预算由运行器维护。模型确需预算信息时使用可复原输入，不要求交付物展示剩余时间，也不持续注入重复倒计时消息。

## 8. 实施分解与模块所有权

### 第一批：恢复目标收敛与确定性起点

- 修改 Recovery Agent/Pack 的通用目标，去掉默认依赖准备倾向。
- 在 Provider 路径支持已确认 base commit 的直接物化，复用现有 Git 隔离和起点校验。
- 必要输入覆盖明确记录；未知起点保持调查回退，不自动猜测成功。
- 在既有结果/事件中表达起点证据及实际环境检查，避免新建复杂 workflow 状态体系。

验收：两个明确 Git 起点无需调用模型安装依赖即可形成可接受 baseline；非 Git 恢复不回退；源保护与历史答案隔离保持。

### 第二批：受管执行工具

- 先检查并扩展 [Runtime 端口](../../src/core/runtime.ts)，再接内置 Pack 与工具适配器。
- 复用 process-runner 增加进程会话所有者、增量输出与结束/取消收尾。
- 在 Recovery 暴露 exec_command/write_stdin，通用能力可以供其他 Agent 复用；不让应用层按产品类型分叉。
- [schema](../../src/core/schema.ts) 对新增持久化、模型和外部 JSON 边界执行 Value.Check；同进程类型边界不重复校验。
- 复用工具事件，补足会话输出与终态事件，使模型实际输入可复原。
- 修正 fatal 错误传播，再开放安全的读取并行。

验收：超过 60 秒的受控测试进程能返回会话并最终成功；取消后无残留写进程；终态前不能封存 baseline；跨会话操作被拒绝。

### 第三批：测量后优化

- 给准备、复制、模型、工具等待、安装、校验、收尾分别计时；记录重叠区间，不能把并行时长直接求和当总耗时。
- 基于瓶颈证据增加包下载缓存；只在确有收益时增加编译缓存或复制优化。
- 比较单项与四项并发运行，区分宿主资源竞争和单任务流程成本。

每批实现同步更新 [Recovery 架构](../architecture/recovery.md)、[执行架构](../architecture/execution.md) 和必要的 [证据契约](../architecture/evidence-and-comparison.md)。提示词、工具面、事件和跨模块边界变化须按 [ADR 规则](../decisions/README.md) 新增或更新决策，并明确替代的旧约束。

## 9. 验证与完成条件

### 9.1 默认离线回归，不产生模型费用

复用现有 fixture，补以下高价值回归：

- 正确 base commit 加必要 dirty/untracked 输入能够恢复；历史结果 HEAD 不能错误通过。
- 必需输入不因依赖排除策略丢失，源目录始终不变。
- 显式验证环境的任务仍能准备依赖；普通恢复不默认安装或全量构建。
- 子进程超过旧 60 秒边界后可续读、正常退出；常规 CI 使用可控时钟/进程夹具，另做真实 Windows 长进程验证。
- 输出分块不丢失、截断可识别、非零退出可见；旧 shell 与旧事件保持可读。
- 取消正在运行的进程树，等待清理后才封存；后台写进程不能绕过资源锁。
- 会话越权/失效拒绝；审计或持久化故障立即终止，不继续接受。
- 新增模型可见输入能由事件复原；真实模型路径仍显式 opt-in。

代码变更先 build 再运行针对性测试，因为测试读取 dist；完成后执行 `npm run check`。只改本文执行 `npm run verify:docs`。若增加门禁，同批提供能使其失败的反向用例；不降低覆盖率要求。

### 9.2 真实验证需单独授权执行

实现后按项目 opt-in 运行两项 Git 恢复和既有鹈鹕/DOCX 非 Git 回归。规划本身不启动这些计费任务。

每项记录：精确版本、期望/实际 HEAD、输入与源指纹、是否接受、各阶段耗时、模型请求与压缩次数、安装命令、输出与取消原因。用量/费用采用供应方真实数据；缺失标为未知，不编造零费用。

首先单项验证正确性，再四项并发验证竞争和收尾。固定任务、模型配置和代理条件，对比冷缓存/暖缓存；缓存预热或宿主工具链准备的时间单独记录，不能隐藏为优化收益。

明确起点的两项 Git 任务须同时满足：

1. baseline HEAD 与上表完整 SHA 一致，原输入正确，历史答案未混入。
2. 默认 Recovery 没有依赖安装或完整构建命令。
3. Candidate 能从该起点开始工作；没有依赖不被错误解释为恢复失败。
4. 原始会话与工作区完整性不变，退出后无受管进程残留。

建议至少连续两轮通过后称“初步稳定”，并记录样本范围；不能把两次成功当作通用可靠性保证。耗时下降是测量目标，现阶段不承诺具体分钟数或加速倍数。

## 10. 兼容、风险与暂缓项

| 风险 / 选择 | 推荐处理 |
|---|---|
| 历史 commit 选错 | 显式起点与推断起点分开；起点不清楚时继续调查或明确失败 |
| 排除依赖误删真实输入 | 依据来源和任务输入记录，不用全局目录名黑名单代替语义 |
| baseline 封存时后台进程仍写入 | 进程生命期资源锁 + 取消/drain 屏障 |
| 缓存污染或历史答案泄漏 | 先下载缓存，候选输入独立，产物缓存后置 |
| 新工具只换名称，底层仍 60 秒杀进程 | 测试真实生命期、输出与取消，不仅测试 schema |
| Prompt 变短但工具仍输出大量日志 | 增量输出、明确截断与按需读取；不默认灌入全日志 |
| 旧 Runtime 不支持会话执行 | 能力声明与同步兼容入口；不谎报支持，不静默降级关键语义 |
| 全局环境被安装命令修改 | 默认无 login 侧效应、工作区内准备、禁止隐式全局配置修改 |

第一版暂缓：完整 Docker 环境系统、所有 Codex 工具照搬、freeform apply_patch 全面兼容、自动多 Agent 编排、自动重试所有失败、所有项目的依赖预热、跨宿主共享编译缓存。

本规划的交付标准是：**起点确定时减少模型和安装工作；确需长命令时工具能够承接；失败时及时、真实地结束。** 实施收益必须由上述回归与真实测量确认。
