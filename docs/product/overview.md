# Reprise 产品定义

状态：当前产品基线

## 1. 产品问题

Reprise 帮助个人用户回答：

> 在我真实完成过的任务上，把 Claude Code 或 Codex 中使用的模型换成另一个模型，实际结果、效率和成本会不会变好？

模型是实验中唯一被有意改变的主要变量；当前 Agent Runtime、会话开始前环境、用户协作能力和运行预算等其他条件应尽量固定。Harness 不恢复历史 Runtime，而是直接使用当前机器已安装的 Agent Runtime，并完整记录本次实际执行的 Runtime、配置、模型解析事实以及所有已知偏差和未知项。因此结果表达的是“模型在用户当前实际 Agent 产品中的个人效用”，不是脱离产品的基础模型纯能力。

它是本地优先、面向少量真实任务的个人对照工具，不是公共榜单、标准 benchmark 或可复现评测集。一两个有代表性的历史任务就可以为个人选择提供有价值的证据。

## 2. 用户工作流

```text
首次使用时通过 Pi 配置 Harness 内部 Agent 模型
→ 选择 Claude Code、Codex 等目标 Agent 产品
→ 选择或发现该产品中的一段高价值历史会话
→ 将这段完整会话冻结为 TaskCase
→ Recovery Agent 与 Environment Provider 恢复会话开始前环境，Harness 解析并记录当前已安装 Runtime
→ 从目标 Runtime 已配置或可验证的模型中选择候选
→ 检查运行条件并创建隔离副本
→ 候选模型在原 Agent 产品中执行任务
→ Controller 根据当前轨迹动态生成后续用户输入
→ 用户查看结果路径，按需发起 Comparison
→ 用户在 TUI 摘要和本地并排报告中自行判断
```

原始完成结果是产品比较中的历史基线事实，不通过 Runner 重放。产品只检验每个候选结果与该原始完成结果之间的差异；即使一个 Experiment 包含多个候选，也不把候选之间的排名作为实验问题。只有候选模型使用的 Agent Runtime 由 Harness 启动和控制。

每个候选模型的执行对应一个独立 `CandidateRun`；它共享同一个 `TaskCase` 和实验条件，但拥有独立的工作环境、运行记录与 trace。

Recovery、Controller 和 Comparison 是三个独立 Agent 模块：Recovery 理解产品相关恢复证据，Controller 只基于规范化会话与当前轨迹模拟用户协作，Comparison 只基于历史结果和候选结果组织展示。它们共享一份内部模型配置，但各自拥有独立的连续 Session 和领域职责。

Pi provider 中配置的是 Harness 内部 Agent 模型；候选模型必须由目标 Agent Runtime 配置、接受并解析，不能从 Pi 模型列表替代推断。完整交互路径见 [TUI 与最小用户交互规划](./tui.md)。

## 3. 产品目标

- 自动发现或辅助选择本机 Claude Code、Codex 等产品中的高价值会话。
- 保留原始历史会话，不把它改写成经典测试题或统一 benchmark 格式。
- 使用当前机器已安装的 Agent Runtime，自动记录其可观察事实，并尽量恢复会话开始前环境。
- 在候选模型轨迹发生变化时，仍提供同等人类能力下的合理后续输入。
- 始终记录时间、token、成本、模型调用、工具调用和停止原因等过程事实。
- 让 Agent 根据任务本身选择值得展示的结果证据，不强制统一质量评分。
- 生成可追溯的本地报告，由用户直接查看产物和证据。
- 恢复证据不足时保存调查结果并停止，不把不足场景伪装为可比较运行。

## 4. 非目标

- 不测量脱离 Agent 产品的基础模型纯能力。
- 不建立适用于所有人的公共排行榜。
- 不把一次运行外推为模型的普遍结论。
- 不要求所有任务都有标准答案或统一指标。
- 不逐字重放原用户的每轮消息。
- 不为所有任务预先设计人工 rubric 或主观分数。
- 不声称能够回滚不可逆的外部世界副作用。
- 不构建新的通用 Coding Agent 或 Workflow Engine。

## 5. “任何任务”的含义

产品在任务类型上保持开放，可以处理编程、浏览器研究、文档与媒体、数据分析、本地自动化或其他多轮 Agent 任务。开放性来自可插拔的 Runtime 和 Environment 能力，而不是承诺每种任务都能严格恢复。

不同环境可能只能达到不同的控制程度：

| 任务环境 | 可能的恢复方式 | 典型限制 |
|---|---|---|
| 本地文件或代码 | 快照、Git、文件历史、隔离副本 | 未提交或被覆盖内容可能没有证据 |
| 文档和媒体 | 输入文件与输出目录快照 | 字体、插件、桌面应用版本可能变化 |
| 浏览器和网页 | 独立 profile、测试账号、页面证据 | 网站内容、登录态和服务行为会变化 |
| 数据库或 API | 测试实例、mock、事务或只读模式 | 真实副作用通常不能安全重放 |
| 私有业务系统 | 隔离账号和明确授权 | 权限、网络和外部状态可能不可复制 |

“任何任务”表示架构不把任务限制为 Git 项目或 CLI 编码任务；实际可比较程度必须由报告中的环境事实说明。首个可交付纵切片只支持 Codex 与空工作目录或已冻结输入文件；Claude Code、浏览器、数据库和复杂非空项目属于该边界通过后的扩展。

## 6. 同等人类能力

候选模型的输出和工具轨迹会与原会话不同，因此后续用户输入也不应固定。Harness 使用 Controller 读取：

- 原始历史会话；
- 原用户表达过的目标、事实、偏好和约束；
- 候选模型当前的消息、工具结果和产物；
- 已经发送给候选模型的用户输入；
- 当前预算、权限和停止条件。

Controller 在每个稳定输入边界决定发送下一条普通用户消息，或者结束运行。它模拟的是同一个有能力的用户面对不同轨迹时会如何继续协作，而不是复刻相同文本，也不是替候选模型执行任务。

用户为三个内部角色选择一份通过 Pi 可用的 provider 与模型配置。Harness 不指定、捆绑、推荐或评价该模型；每个角色在自己的 Session 中使用启动时配置快照。

具体契约见[Controller 设计](../architecture/controller.md)。

## 7. 历史任务与 TaskCase

用户选择的一段完整逻辑会话会被保存为不可变的 `TaskCase`。整段会话默认就是一个真实任务，不从中自动发现、评分或切分子任务。TaskCase 包含完整 transcript、第一条可执行用户输入、原始结果证据、来源 Runtime 证据、Environment 证据和隐私策略，但不要求重新编写任务或制作标准答案。来源 Runtime 证据只用于解释历史会话，不参与候选 Runtime 选择或环境匹配。

候选 Runtime 从该会话的第一条可执行用户输入开始；Controller 可以读取完整原始会话，并根据候选当前轨迹自主决定后续输入，而不是逐字重放历史用户消息。历史会话的结束不限制候选运行轮数，停止由 Controller 的用户协作判断、预算和显式取消共同决定。

`TaskCase` 的公共模型见[架构总览](../architecture/overview.md)。

## 8. Runtime 与环境条件

模型是实验中唯一被有意改变的主要变量，Agent Runtime 是应尽量固定并完整记录的实际使用条件。Harness 直接解析当前机器已安装的 Claude Code、Codex 等 Runtime，不要求用户选择版本，也不下载、缓存或重建历史版本。每次候选运行自动记录可观察到的 executable、产品、版本、provider 与模型解析结果，以及工具、MCP、权限、沙箱、上下文压缩和重试等关键配置；闭源产品无法暴露的内部行为记录为 `unknown`，不能用推测补齐。

历史会话中的 Runtime 信息作为 `SourceRuntimeEvidence` 保留，用来解释原始结果来自什么条件，但不参与候选 Runtime 解析、环境 fidelity 或实验有效性判断。历史版本与当前版本不同不是 mismatch 或 warning。同一个 Experiment 的首个候选准备时建立当前 Runtime 基准，并在每个候选启动前重新探测；若 executable、版本或关键配置在候选之间意外变化，记录 `runtime_drift` warning，但允许运行继续。

候选运行总是在恢复后的环境中创建新的 Runtime session，从 `TaskCase.initialInput` 开始。历史 session 的 resume 只属于 Product Pack 可能提供的会话读取或诊断能力，不是候选运行的必要路径。文件、Git 状态、依赖、登录态、外部服务和网页状态由独立的 Environment 子系统处理。恢复细节见[Environment 设计](../architecture/environment.md)。

Runtime 的 CLI 兼容性不建立独立的运行前验证产品。Claude Code、Codex 等适配器在开发时通过最小契约测试验证启动、输入 admission、turn settlement、多轮发送、停止和错误分类；Candidate Run 只记录适配器实际观察到的事件和版本事实。

## 9. 结果与报告

报告始终展示能够直接记录的过程事实：

- 总墙钟时间和各阶段耗时；
- 模型调用、token 与可获得的成本；
- 工具调用、失败、重试与权限等待；
- target turns、Controller 消息和停止原因；
- 当前执行 Runtime 的可观察事实与实验内漂移 warning，以及 Environment 和外部状态的匹配或未知项。

任务结果不设统一分数。产品无关的 Comparison Agent 只根据历史任务、原始结果、候选结果、artifact 和客观遥测，选择适合并排查看的文件、diff、截图、命令输出、网页状态或其他证据，并说明为什么展示它们。Comparison Agent 直接生成报告；Host 只验证薄信封、证据归属和路径；用户直接查看证据和最终产物，自行判断功能完成度、设计质量和实际可用性。具体契约见[Comparison 设计](../architecture/comparison.md)。

报告不得把 Agent 自述、已执行检查、Harness 观察和独立验证混成同一种证据。

## 10. 结果解释

比较条件不是一个互斥状态，而是多维事实：当前执行 Runtime 是否一致、环境是否恢复、外部世界是否受控、实际模型身份是否可验证。Harness 根据环境和证据质量将结果概括为：

- `strict`：关键条件匹配且证据充分；
- `exploratory`：环境存在 mismatch、兼容接入或关键 unknown；
- `observational`：任务主要依赖无法恢复或控制的外部状态。

这些标签只描述证据强度，不表示任务成功或模型质量。

## 11. 安全与隐私

- 默认在 Harness 拥有的隔离目录中恢复和执行，不直接覆盖用户当前工作区。
- 原始凭据不写入 trace、prompt 或报告；发送给外部模型的内容受 `TaskCase` 隐私策略约束。
- Harness 不下载或切换 Runtime 版本，也不修改用户的全局 Runtime 安装；候选配置只写入隔离运行环境。
- 真实发布、删除、付款、迁移或权限扩大不能由 Controller 推测授权。
- 无法安全隔离的外部副作用应使用测试账号、mock、只读观察或终止运行。

## 12. 产品原则

```text
真实任务，而不是经典题目
动态协作，而不是消息 replay
证据展示，而不是统一打分
诚实降级，而不是假装公平
少量明确原语，而不是评测平台
```

## 13. 凭据

模型服务 API 密钥可作为 `apiKey` 持久化在本机、Git 忽略的 `.reprise/harness-model.json` 中，或继续使用 `env:NAME` 引用。官方 Pi catalog 登录只存在 `~/.pi/agent/auth.json`。密钥值不得提交、打印、写入事件、artifact 或报告。候选 Runtime 的 Codex / Claude 凭据仍由用户本机登录态提供，Reprise 不读也不保存。

系统架构、公共协议和生命周期以[架构总览](../architecture/overview.md)为唯一来源。
