# 决策：以 Session、Reprise harness 和 workflow 收敛重构目标

状态：proposed

## 问题

重构需要集中会话、工具权限、业务检查和生命周期的所有权。六层架构把业务产物、状态机、输入准备和审计均提升为公共基础模块，仍可能让一个业务决定散落于多个所有者。用户要求共用成熟 Agent 执行机制、完整本机历史和三平台本机运行。

## 决定

目标设计经用户确认，完整边界与验收统一见[重构规划](../../plan/reprise-architecture-redesign.md)。本记录位于 proposed 是因为实施及现行规范迁移尚未生效，不表示需要重新征求设计确认。

选择以 Pi 可用 Agent 能力为底座，Reprise 管理 Session 记录和执行约束；业务检查与 CandidateRun 状态由 harness 拥有，普通 workflow 组织用户入口。三个角色共用模型配置，各自连续使用独立 Session；Controller 模拟原用户，不强制独立 Understanding、Host 账本完成守卫或 Planner/Reporter 双会话。

用户运行中只查看和取消；恢复证据不足停止解释；对照从已保存运行结果独立发起。本机历史支持查看全过程，不要求恢复执行、跨机查看或跨系统重放。Windows 使用 PowerShell，macOS/Linux 使用 Bash，三平台支持通过实际验证成立。

CLI 与 TUI 共用应用操作并功能对等，完整 run 与 prepare → run --scenario → compare 分步执行共用实现。活动所有者通过随进程生灭的本机控制端点接收其他终端的 cancel，保持每实验单写者；取消接收与终态清理完成分别表达。

Product Pack 通过显式配置的本地 JavaScript、TypeScript 编译产物或已安装包启动加载，首版作为可信本地代码。采用版本化窄契约、独立能力声明与公共活动数据，内置及外部插件使用同一套契约测试。现有 API 内接入产品只需插件与配置，不修改宿主源码；旧实验查看不依赖原插件。对照消费封存快照，Controller 协作策略和真实能力证据均可追溯。

TUI 采用键盘优先的斜杠入口、分层列表选择和本地产物链接；按键提示代替按钮工具栏。TUI 的目标交互见[阅读与交互规划](../../plan/reprise-tui-design.md)：单窗口连续时间线，保留公开进度，折叠工具与长篇公开摘要；优先拖选阅读，搜索可见消息与活动标题。插件提供通用活动事实，宿主负责展示。真实终端交互以平台验证为准。

## 备选方案

**双窗口与原生 TUI 嵌入。** 同会话附着能力依赖产品，且容易引入人工输入及终端控制冲突；统一只读活动时间线满足查看需求，不提供第二窗口。

**六层与五件套内核。** Workbench、Brief、Verifier、Audit 各自成为基础子系统会把业务权限、完成规则和输入形式强行统一；这些职责跟随工具、角色和记录所有者即可。

**完整自研通用 Agent 框架。** 重复 Pi 已有模型适配与循环，没有独立产品需求支撑；只补经验证的具体缺口。

**直接采用全部 Pi AgentHarness API。** 所检查的 0.84.1 高级接口存在占位实现，不能把接口声明视为可用保证。

**跨机可移植与断点续跑。** 用户仅需本机历史查看；这些能力扩大格式、环境和副作用恢复范围。

**统一 Bash。** 用户选择原生 Windows PowerShell 路线，不以安装 Git Bash 或 WSL 作为前置要求。

**CLI 模拟 TUI 或另写编排。** 无法保证业务行为与测试一致，CLI/TUI 各自调用公共应用操作即可。

**静态源码注册或插件市场。** 静态注册要求改宿主源码，不满足独立接入；市场、热加载及不可信代码隔离超出当前范围，采用显式本地配置。

**后台服务统一调度或按 PID 直接取消。** 前者增加常驻生命周期，后者有 PID 复用和清理语义问题；活动所有者接收本机请求并执行统一收尾。

## 影响

减少通用抽象与强制模型调用，保留完整历史、证据隔离、投递不确定性、清理与任务结果分离等必要约束。代价是平台实现和权限能力必须分别验证，Pi 存储及压缩复用需要先做行为检查。

对应实现批次必须同步调整当前 Controller、Comparison、恢复接受、schema 与平台规范及受影响决策。代码迁移前不移动或改写描述当前行为的 accepted 记录；不宣称目标能力已经可用。
