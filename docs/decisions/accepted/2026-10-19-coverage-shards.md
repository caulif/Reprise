# 决策：覆盖率在独立 runner 分片并统一汇总

状态：accepted

## 问题

完整串行覆盖率 CI 曾用时约 37 分钟。单纯增加同机测试并发会重新引入浏览器争用；只延长预算不能缩短反馈周期。

## 决定

根据历史逐文件耗时，按慢文件优先、分配到当前预计负载最小分片的确定性算法分成 4 片，分别在独立 Ubuntu runner 内串行执行，完整测试集合恰好分配一次。每片保留测试断言和临时目录守卫；只有成功完成后才发布 manifest 与原始 V8 coverage。覆盖率运行保留原有测试断言，并承担 Linux 测试门禁，移除同平台普通测试的重复执行；Windows/macOS 普通测试和 Windows 审计保留，Linux CLI smoke 在第一片执行。独立浏览器诊断只在分片失败后运行，不阻断也不替代测试。

汇总验证完整分片集合、文件分配、提交、Node 版本、工作区绝对路径、构建与工具摘要、报告文件清单及 SHA-256。缺片、重复、数据损坏或身份不一致均失败。各 runner 使用相同 checkout 路径，路径不一致时拒绝合并，避免绝对源码 URL 失配。

由一个显式运行的辅助测试把验证后的原始报告导入 Node 原生 coverage collector 活动目录，继续使用 Node 自身的范围合并、忽略注释和阈值计算。全局阈值保持 lines 88、branches 76、functions 87，排除范围沿用原配置；分片不检查局部百分比，也不取分片百分比平均。辅助文件不匹配普通测试 glob，位于原有 test 排除范围内。

调度权重取自已完成的 Ubuntu 串行覆盖率 CI 的可归属顶层测试耗时，不是超时或性能承诺。新增文件使用默认权重；每片输出新的逐文件 timing artifact，后续核对后更新权重。所有测试仍恰好分配一次，身份摘要也绑定调度配置，防止不同计划混用。

纯文档 PR 使用保守 Markdown 白名单，保留整个 static lane，仅跳过平台测试、TUI 审计及覆盖率。AGENTS、运行时 SKILL、未知路径和空差异都走完整门禁。范围计算覆盖整个 PR 的 merge-base 差异，关闭 rename 检测以同时检查旧路径删除；main push 始终完整执行。最终 aggregate 必须验证范围检测和 static 成功，代码变化的全部测试作业成功，或文档变化的重型作业按预期 skipped；检测失败、取消和无效输出均不能放行。

分片墙钟预算 30 分钟、汇总 15 分钟；最终 aggregate 继续要求 coverage 成功。保留本地完整覆盖率命令。原始报告只保留一天，失败片不产生成功 manifest。该方案替代[单作业预算决定](2026-10-18-coverage-job-budget.md)，延续[同机并发限制](2026-10-06-linux-ci-test-concurrency.md)。

## 备选方案

**同机提高覆盖率并发。** 浏览器竞争风险未消除，不采用。
**自写百分比合并或增加第三方覆盖率引擎。** 可能改变统计语义，选择原生引擎。
**仅跳过慢测试或降低阈值。** 削弱门禁，不采用。

**覆盖率以外再跑同一份 Linux 测试。** 没有增加平台或断言覆盖，移除重复执行。

**文档路径直接跳过整个 workflow。** 会让 required check 缺席，也无法验证生成文档与秘密，采用始终运行 static 和 aggregate 的路径。

## 影响

多 runner 会增加安装、构建和 artifact 开销，也增加并发资源需求；队列可能抵消部分提速。历史权重不能预测所有机器和后续代码的耗时，真实远端加速需要实测。文档快速路径仍安装依赖和构建，以保留生成区与供应链检查；不通过只看最后一次提交或 GitHub 截断的文件列表判定范围。Node 升级需重跑原生合并集成回归。

## 验证

自动化用例验证分片完整且无重叠、非法分片拒绝、互补分支合并与串行统计一致，并构造缺片、重复、身份失配、清单失配、报告损坏、失败 worker 及全局覆盖不足，确保全部拒绝。workflow 反向用例验证不能移除分片依赖、漏片或绕过全局汇总。分片规划测试验证负载均衡、确定性和新文件完整分配；范围测试覆盖代码混入、指令文件、路径穿越、真实 Git 重命名、main push，以及失败/取消/意外跳过的 aggregate 拒绝。修改代码执行 build、定向测试及 check；远端结果与本地验证分别报告。当前命令入口见[开发指南](../../development.md)。
