# 决策：以唯一归宿和迁移边界维护文档

状态：accepted

## 问题

清理文档后，目标规划遗漏部分已确认行为，当前规范夹带旧规划，prompt 与类型全文副本造成多处维护。直接按讨论改写所有当前规范又会把未实施功能误当作可用接口，影响贡献者与 coding agent 判断。

## 决定

文档按[结构与生命周期](../../documentation-structure.md)维护。当前规则、目标计划、理由与完成证据分别有唯一归宿；README 提供按任务阅读路径。proposed 允许承载已确认但未实施的目标，必须明确确认状态与生效条件。

当前到目标的差异集中在[迁移边界](../../plan/documentation-reconciliation-for-session-harness-workflow.md)，已确认设计不因旧 ADR 存在而重新审批，也不因改文档而宣布代码已迁移。目标细节恢复到架构与 TUI 两份各司其职的计划，A1–A18 属于架构目标验收。

类型、工具注册、prompt、依赖和 CI 配置由代码拥有。文档保留语义、权限与失败边界，链接实际定义，删除重复全文和独立专题路线。受控说明不依赖被忽略的本机 HTML，原型只演示目标的部分交互。

本决定仅改变文档维护方式，不替代仍在当前实现生效的运行协议、恢复策略或会话安排。代码迁移时才按对应验收替代那些 ADR。

## 备选方案

**将全部规范直接改成目标设计。** 无法诚实表达当前 CLI、Session 和插件能力，会误导使用者与后续修改。

**保留所有设计并靠日期选最新。** 重复 prompt、类型和专题规划会继续漂移，读者无法确定要修改的归宿。

**增加另一套文档框架和定期清理系统。** 当前链接、预算及目录门禁已可复用，增加独立台账或自动任务没有必要；语义一致性仍需结合代码审查。

## 影响

减少重复说明与导航跳转，保持开源检出可读。代价是迁移 PR 必须同步代码、规范和替代关系；门禁不能替代语义复核。历史设计仍可在 Git 追溯，不把本机归档作为规范来源。

## 验证

运行 npm run verify:docs，核对链接、目录、命名、ADR 模板与预算。人工对照已确认讨论检查目标验收、CLI/取消/插件边界及键盘 TUI；抽查实际 CLI、Pack 注册和平台实现，确保 README 与当前支持声明不超出代码或验证证据。
