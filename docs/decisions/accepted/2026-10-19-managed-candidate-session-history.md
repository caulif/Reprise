# 决策：候选会话持久化与受管历史归组

状态：accepted

## 问题

Codex 候选使用临时 thread，Claude Code 候选关闭原生会话保存，导致实验退出后无法通过原生正文检查候选过程。即使原生日志存在，上游清理也不保证长期保留。按每次候选工作副本路径归组，会把同一工具的 Reprise 会话拆成许多项目。

Claude 历史输入索引另有两个问题：缺少正文被误报为不可读，有项目路径的索引却按未知来源为每个会话创建独立项目。来源完整度和项目归属不能互相替代。

## 决定

内置候选 Runtime 保存原生会话。持久化能力从 core Runtime 端口声明，Pack 负责产品来源定位和解释，应用层负责归档、运行归属及发现合并。旧 Pack 缺少能力时不补造原生正文。模型目录探测和内部 Harness 调用不因候选持久化而改变策略。

每个产品下的受管候选会话统一显示在 Reprise 逻辑项目中，保留实际实验、run、原生 session ID 和工作副本路径。列表归属不改变进程 cwd，不共享候选工作副本，也不改变登录或自动记忆配置。已有原生日志和受管副本按产品及会话身份去重。

归档在 Runtime 收尾后读取原生正文，并检查来源根、真实路径、内部会话 ID 和工作目录。持久化描述及外部读入遵守 core schema 校验。归档读取失败、源变化或收尾取消保留诊断，不能用“请求了保存”代替“已验证正文存在”，不能用归档失败覆盖原任务错误。

受管历史属于本机数据目录，不复制工具配置目录或凭据。归档保留过程证据，原生正文被清理后仍可读取有效副本。正文包含模型输入输出及工具内容，应与本机实验数据一样保护，不提交仓库。浏览和完整恢复资格分别判断，不能因出现在 Reprise 项目中自动证明它适合作为新历史基线。

本批归档对象是经检查的主 JSONL，单份上限 64 MiB；子代理、附件及溢出工具结果仍遵守产品已有支持边界，不宣称随主日志完整保存。原生来源被清理且未成功归档时只能展示缺失诊断。浏览列表使用有界摘要，选择详情后再完整校验正文；坏的单份描述不能使其他有效会话消失。

历史输入索引继续按已有 history 证据读取，有有效项目路径时正常归组；仅索引、实际读取失败和待完整检查分别展示。单个坏文件不使其他来源消失；子代理和备份不作为普通主会话。共享读取预算、取消和完整检查要求继续生效。

Codex 原生历史在配置的 `sessions` 及其同级 `archived_sessions` 中发现，兼容明文和 zstd，按会话身份去重。原生归档仍是可读取来源，不因移入归档目录降为仅索引；这与 Reprise 自身的受管副本是两种保存位置。归档根必须为普通目录，索引绑定继续核对所属根、真实路径及内部会话 ID；不扩大到任意同级目录，不沿归档根链接读取外部文件。显式指定其他名称的自定义来源根不自动扩展目录。

## 备选方案

**统一所有候选 cwd。** 会改变实际运行环境并破坏工作副本隔离，拒绝。

**只开启原生保存。** 无法抵御原生日志保留期和目录变化，不能满足受管历史长期可读取。

**复制整个工具 home 或重写原生数据库。** 会引入凭据复制、配置漂移和未公开写入契约，不采用。

## 影响

旧实验不迁移，不从事件投影伪造原生正文；缺少受管归档时继续使用原有来源。新读端识别有效归档，旧读端不把新增归档作为运行状态来源。

Claude Code 的全局保留设置属于用户本机配置。当前官方要求 cleanupPeriodDays 为正整数，没有合法的永久关闭值；本 ADR 不修改用户配置，也不以非法值或溢出数字冒称关闭清理。

## 验证

离线验证覆盖两个 Pack 的持久化启动参数、已创建但首轮失败的会话绑定、归档身份与路径拒绝、重启发现、去重、原生源缺失及归档损坏；发现回归覆盖已知项目索引和逐文件错误隔离。测试不替代真实 Runtime 兼容验收；真实调用仍需显式授权与 opt-in。
