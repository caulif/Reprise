# 决策：冻结任务保全优先于原路径修正

状态：accepted

后继：[版本化冻结身份](2026-10-14-frozen-case-identity.md) 完成不同起点并存，保留本决定的不覆盖旧证据原则。

## 问题

现行 case ID 和 contentHash 由来源会话 hash 派生，不绑定选定起始消息。此前共享冻结入口会删除已发布目录再按新起点重写；JSON 读取失败也可能进入替换。这会改变旧实验依赖的任务，并在后续写入失败时丢失旧证据。

## 决定

共享冻结发布只创建缺失的目标；已存在的目录不删除、不替换。幂等复用必须经过核心 TaskCase schema 校验、明确的版本支持检查和完整标记读取，再按 JSON 持久化语义规范化预期值并对比冻结内容，仅忽略本次重试的 importedAt；显式 undefined 的可选属性与省略属性等价。选择或证据不同、格式损坏、未来版本或未完成目录都拒绝，不静默修复。并发方已发布目录只能按同一规则复用。

## 备选方案

**原地替换旧 case**：虽然允许立即切换任务起点，但会改变旧实验引用，并在写入失败时丢失原证据，因此拒绝。

**立即改变 TaskCase 身份格式**：可以支持不同起点并存，但需要同时处理旧引用、兼容读端与目录发布占有协议；本批先保全证据，后续单独实施。

## 影响

这批止损保持 schema 和来源派生身份不变；不同起点暂时冲突，不能靠覆盖原目录解决。后续版本化身份与发布占有协议独立实施，并保留旧实验引用；本决定不承诺附件内容完整审计、断电持久性或新目录并发原语。

## 验证

回归检查两个起点冲突、AGENTS 自动跳过、重复冻结跨 importedAt 幂等、损坏/未来版本/错误内容/缺标记，以及写入和 rename 失败时并发已发布目录的原始文件 hash。任何失败只清理本次私有 staging。当前契约见[证据与持久化](../../architecture/evidence-and-comparison.md#冻结任务保全)。
