# 决策：区分未有提交的源仓库与不可用 Git 证据

状态：accepted

## 问题

原始任务可能发生在已初始化但尚无提交的目录中。Recovery Agent 已删除后继成果并返回 ready，Host 却将正常的无提交状态归为 Git 证据不可用，反复要求 Agent 修复一个不存在的历史提交。失败页又根据缺少校验预览推断零变更，显示没有观察到变更，与已记录的删除动作冲突。

## 决定

新冻结 Git 证据使用 schemaVersion 2，新增独立的 unborn 状态；读取端继续接受版本 1，但不重新解释其中的 unavailable。分类必须观察正常工作树、符号 HEAD 指向未创建的本地分支、没有 refs/reflogs 可达提交，并通过完整对象检查且没有遗留提交。原始历史中的提交回执或 historicalCommit 与空仓库矛盾时仍记为 unavailable；这不是将线索当作指定 gitStart。孤儿分支、丢失引用但仍有提交对象、损坏或探测失败不能变成正常无提交。

只有冻结源证据明确为 unborn 时，Host 才允许副本保持相同无提交状态，并检查保留的 dirty 文件与受保护 source 字节一致。原有 Git 提交映射、任务成果提交拒绝、源目录 tripwire、路径边界、显式 gitStart 规则继续生效。取消不得被冻结证据的诊断 catch 吞掉。

Agent 负责依据原始历史判断必要输入和后继材料，不需要编造提交；与当前 source 一致不能证明文件早于任务。关键输入或答案边界不清时仍需 blocked。该提示词随既有 Session 审计记录，不新增隐含模型输入。Host 机械通过不认证历史语义，也不把 blocked 改为 ready。

失败摘要按真实 failureStage 展示，不从 changedPathCount 推断 no_task_path_outcome；即使实际零变更也不等于恢复失败，任务前状态可能本来就无需修改。

## 备选方案

**统一拒绝无 HEAD。** 使正常无提交任务无法开始。

**统一信任 Agent ready。** 丢失损坏仓库与伪造提交的机械防线。

**补首次提交或只改提示。** 前者创造历史事实，后者不能解决无提交场景的错误拒绝。

## 影响

正常无提交场景可依据 Agent 调查和机械检查进入接受流程；不扩大文件写入范围，也不重写旧 run。版本 1 仍可读取，新版本证据不保证能被旧程序识别；回退后保留新记录，另建旧版兼容实验，不覆盖旧记录。没有实际提交时不执行 Git 历史封存，不宣称证明了文件的历史归属。

## 验证

离线自动化覆盖真实 Git 初始化后的冻结、输入变更拒绝、新造提交拒绝、孤儿分支及遗留提交拒绝、损坏诊断、取消传播、旧 schema 读取，以及 Agent 删除成果后的完整 Recovery 接受和 blocked 保留。TUI 验证零变更与未知变更均不伪造无成果错误。既有有提交仓库回归继续验证任务成果和无关提交被拒绝。测试不证明真实模型能正确识别历史材料，也不宣称截图任务已通过真实重跑。
