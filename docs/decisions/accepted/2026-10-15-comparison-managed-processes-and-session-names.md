# 决策：Comparison 复用受管进程，对外只区分历史与当前

状态：accepted

## 问题

Comparison 的同步 `shell_exec` 默认在 60 秒后终止命令，模型既不能延长等待，也不能继续读取仍在运行的命令。一次长测试因此被升级为整个比较失败；Recovery 和 Controller 已有的受管进程能力未接入 Comparison。报告表头虽使用历史/当前，固定文案和作者提示仍混用候选/基线，容易混淆执行模型与报告分析模型。

## 决定

正式 Comparison 与 coding 试验复用现有 `exec_command`、`write_stdin`、`cancel_process`。默认等待 10 秒后返回进程状态和句柄，等待长度不决定进程生命期；整体任务截止和显式取消继续有效。模型应完成或取消命令再结束 invocation，不能以后台进程尚未收尾的状态发布成功报告。工具包装器必须转发 Session/invocation owner，保留生命周期回调。

命令非零退出是可检查的结果；已知的无副作用前置条件拒绝允许模型纠正。未知工具故障、审计/日志持久化失败及无法确认终止继续致命，不把所有异常转成成功文本，不自动重新执行有副作用的命令。复用已有共享错误类型，目录链接遍历的修复不属于本批。

浏览器执行限制与只读挂载检查覆盖新的命令入口；进程输入也属于执行边界。进程仅能由同一 invocation 操作，同一工作区的冲突操作继续互斥。输出沿用增量脱敏、分页、截断标记和有界日志，正式日志按当前运行登记 artifact。这里没有新增 OS 沙箱、PTY、跨宿主重启进程恢复或第三套进程管理器。

参考固定版本 [Codex 的持续进程参数](https://github.com/openai/codex/blob/bb64b894fd67158be0f874872e6d7bfe717e7368/codex-rs/core/src/tools/handlers/unified_exec.rs) 与 [进程管理](https://github.com/openai/codex/blob/bb64b894fd67158be0f874872e6d7bfe717e7368/codex-rs/core/src/unified_exec/process_manager.rs)。借鉴等待返回和进程寿命分离的契约，不声称复制其审批、终端或平台默认值。已有基础见[受管进程决策](2026-10-12-lightweight-recovery-and-managed-processes.md)。

用户可见的两侧名称统一为“历史 / 当前”（History / Current），包括报告、图注、状态及生成提示。当前模型来自实际运行解析结果，不能由请求别名、Controller 或 Comparison 模型补位；未记录保持未知。报告分析模型可以作为独立来源信息展示，但不是第三个比较对象。任务起点快照不改称历史会话。

内部 `candidate`、`baseline` 字段、路径和已有事件保持兼容；原始引文、历史文件和模型的技术引用不做全局词语替换。Token 聚合、缓存口径、价格表和指标计算不变。

## 备选方案

**仅提高同步命令超时。** 仍无法观察长命令、继续输入或有依据地取消，且继续保留两套角色行为。

**仅切换工具开关。** owner、命令拒绝包装和日志归属仍可能断开，不能视为完整迁移。

**全面重命名持久化字段。** 文案问题不需要破坏已保存实验及第三方读取契约。

**所有错误继续。** 会掩盖审计失败和未知写入结果，拒绝采用。

## 影响

撤回代码恢复旧工具装配和文案，不需要修改旧事件或数据目录。已经完成的新报告保持原字节；失败日志不能被改写成成功。任意 shell 仍具有宿主权限，不能把命令检查称为 OS 隔离。

## 验证

回归覆盖真实工具装配、等待后继续读取、非零退出、错误句柄纠正、浏览器限制、owner 转发、日志登记及未完成/致命失败不能发布；报告回归使用不同的执行与分析模型验证标签归属。先构建再运行 dist 测试，收尾执行 `npm run check`。离线 Provider 与进程 fixture 不证明原始任务或计费模型已经重测。
