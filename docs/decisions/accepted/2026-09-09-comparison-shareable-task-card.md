# 决策：Comparison 生成可分享的真实任务比较卡

状态：accepted

它替代[任务建议与可视化报告旧提案](../superseded/2026-09-08-comparison-task-verdict-and-visual-report.md)。当前运行规范见[Comparison 架构](../../architecture/comparison.md)。可执行 prompt 以 [`comparison-agent.ts`](../../../src/agents/comparison-agent.ts) 为准；[实施参考](../../plan/comparison-task-card-implementation.md)只保留设计草案。

## 问题

模型榜单和真实使用体验经常不一致。用户需要看到同一任务中两个模型的实际交付、关键过程和代价，而不是只看到抽象分数。比较结果还应能被任务参与者复盘，并以一张易懂的卡片分享给不了解内部背景的人。

## 决定

Comparison 的 HTML 首屏定位为**真实任务比较卡**。传播力来自具体反差和实际交付物：读者应能一眼知道任务是什么、比较了哪些模型、两边交付了什么、最重要的差异是什么，以及本次是否有足够收益值得替换。

主结论只存在于 HTML 和现有 `headline`，不新增结构化推荐字段，不生成场景建议或跨任务排名。Comparison 只对本次任务作出选择建议；读者是否把结果迁移到其他任务，由读者自己判断。

首屏的创作目标是让读者迅速看懂任务、比较对象、具体反差和本次判断。有表现力、能揭示真实差异的交付物可以直接成为首屏主角。由 Agent 决定选什么、展示多少、如何组织，不限制交付物类型，不规定差异数量或固定版式，也不要求所有信息块挤入首屏。

时间、token、速度、费用等硬指标保持顶部易见的并列展示；任务背景、身份、建议和用户剩余工作由 Agent 围绕具体发现自然组织。阅读层级是设计引导，不是必须生成的三个区块。

独立的“证据与口径”区块不作为用户可见内容。证据仍是判断和审计的依据，必要限制就近附在对应结论或指标旁。详细过程、原始片段和证据可以折叠展开。

一次 attempt 创建一个连续 Session，Host 依次发送四条工作委托：理解任务、调查与准备、创作比较卡、审阅并交付信封。turn 指一次完整工作委托，内部可以包含多次模型请求和工具调用。前三轮是自由文本；第四轮才校验薄信封。不设置 Comparison 专属执行预算或请求截止。`observations/user-inputs/INDEX.tsv` 在第一轮之前落盘。

完整阅读层级、资料入口与表达纪律见[Comparison 架构](../../architecture/comparison.md)。

## 备选方案

**只生成用户决策卡。** 便于快速选择，但不利于传播和复核。保留决策卡首屏，同时提供可展开的实际交付和过程内容。

**固定报告模板。** 能统一布局，但无法适应代码、页面、文本和数据任务的不同实物。选择以 prompt 说明阅读目标，由 Agent 自主安排内容与视觉形式，不固定信息顺序。

**新增结构化推荐字段。** 便于 TUI 读取，但会扩大协议并诱使机器消费者把单次结论当评分。暂时只用 HTML 与 `headline`，需要聚合时另行决策。

## 影响

Comparison 从“列出差异供用户判断”扩展为“用具体任务证据作出本次建议，并生成可分享比较卡”。现有证据归属、离线、自包含、失败不覆盖成功报告等边界保持不变。

首屏可传播性成为重要质量目标，但不能靠夸张视觉、截取偏向片段或隐藏限制获得。硬指标和交付截图必须以实际采集为准；旧历史数据缺失时保留“未采集”。分享区域需要避免凭据、私人路径和不应公开的原文。

这个定位补充而不是替代通用榜单：它提供具体任务和条件下的实物证据，不能单次证明模型的总体能力。多份独立比较卡可由用户自行形成经验，但本模块不在本次任务中生成跨任务排名。

## 验证

`test/comparison-agent-phases.test.ts`：一次 `compare()` 一个 Session、四次委托，前三轮散文不修 JSON，仅末轮信封。`test/observation-files.test.ts`：`observations/user-inputs/INDEX.tsv` 顺序与来源。`test/harness-agents.test.ts`：Comparison `timeoutMs: 0`。`test/comparison-report.test.ts` 与 `test/codex-experiment.test.ts`：facts 缺失不补零；失败不覆盖成功报告。审美与真实模型比较卡不进确定性门禁。`npm run check` 必须通过。
