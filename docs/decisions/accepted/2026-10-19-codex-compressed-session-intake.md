# 决策：Codex 压缩会话的完整导入与冻结

状态：accepted

## 问题

Codex 可将冷会话正文从 `.jsonl` 转成 `.jsonl.zst`，数据库仍可保留逻辑明文路径。Reprise 原先只扫描、读取明文，将有效压缩正文降为“仅索引”。仅增加后缀过滤也会使共享冻结器将二进制当作 JSONL 复制，绕过正确脱敏。

研究固定到上游提交 `89461ea6833832b0551ce24ee32205824d5c108d`：[维护与透明读取](https://github.com/openai/codex/blob/89461ea6833832b0551ce24ee32205824d5c108d/codex-rs/rollout/src/compression.rs)、[明文优先的物理路径](https://github.com/openai/codex/blob/89461ea6833832b0551ce24ee32205824d5c108d/codex-rs/rollout/src/compression/path_metadata.rs)、[共享客户端兼容要求](https://github.com/openai/codex/blob/89461ea6833832b0551ce24ee32205824d5c108d/codex-rs/app-server/README.md)。该版本存在启动及 RPC 压缩触发，冷文件阈值为最后修改七天；这不是对所有历史版本的断言，也不能仅据本机时间戳确定具体触发者。

## 决定

### 身份和存储表示分离

Codex Pack 扫描明文和压缩正文，物理同胞并存时优先明文。目录绑定解析同目录的明文/压缩表示，保留根包含、普通文件、真实路径和内部 session_meta ID 校验。优先明文损坏或 ID 不符时不回退到可能过期的压缩正文。仅来源切换引发的 ENOENT 可有限重试三次、间隔 50 ms；权限及解码失败不适用重试。

默认仍扫描配置的来源根；显式指向归档根可以读取其中正文，不隐式扩大到所有兄弟目录。CODEX_HOME 选择和显式 root 延续现有 Pack 入口。索引是目录增强，独立正文仍可在索引不可用时被发现。缓存及分页沿用物理文件指纹，变化后需刷新。

### 通用字节读取，Pack 解释事件

共享读取器接受 identity/zstd 编码，默认保持既有明文契约。Codex Pack 负责来源定位和事件解释；应用层不按产品名判断，不扩展 Runtime 端口。摘要、详情、导入和冻结使用同一个解码入口，Claude 明文读端保持兼容。

采用 Node 内置流式 Zstandard，不增加解压依赖或 shell 调用。最低支持版本 Node 22.19.0 及 Windows Node 24.11.1 均须通过夹具验证。能力缺失给出 unsupported-encoding，不在模块初始化崩溃。

不能仅依靠原生解码器判断 EOF：在上述 Node 版本的实际探测中，同步解码只返回串联帧的首帧，并可接受部分截断帧。因此共享帧读取器核对 magic、头部、块边界、可选校验和字节及内容长度，逐帧交给原生解码，拒绝不完整或非法尾部，支持串联及 skippable 帧。校验和内容由原生解码器验证，不另写解码算法。

列表头部 256 KiB、摘要 4 MiB 等窗口按解码字节计；早停只表示预览，不认证完整帧。完整读取默认上限为 512 MiB、单行 16 MiB，同时至多两个压缩读取任务；原生解码窗口上限为 128 MiB。它们是 Reprise 资源边界，不是 Codex 格式限制。超限、损坏和不支持必须显式失败，不能截断后当作完整正文。取消和早停关闭输入及解码管线并释放并发名额。

### 冻结核对完整正文

Codex 全量导入在读取解码字节时计算 SHA-256 和长度，作为进程内 receipt。冻结将解码正文写入 Reprise 私有临时文件，并在脱敏前核对 receipt，防止已解析正文与封存字节不同；变化后拒绝发布并要求刷新检查。

ImportedRawFile 只增加可选编码及 receipt，不改变既有 Pack 的缺省语义。receipt 属于同进程类型边界，不写入报告或模型输入，不增加重复运行时校验。外部 JSON 和持久化边界继续遵守核心 schema 校验。

冻结输出仍是 UTF-8 raw/session.jsonl，保留解码字节和既有脱敏行为，禁止将压缩二进制改名为 JSONL。provenance.sourceHash 继续表示脱敏后来源字节；相同解释版本、隐私及其他任务内容下，压缩与否不改变 case 身份。旧 case 不迁移、不重写、不补认证。

本次临时解码文件由 freezer 关闭并清理；来源 Codex 目录保持只读。不调用压缩、恢复、fork 或 turn 接口，不修改上游日志、索引或锁。读取来源不等于启动候选 Runtime。

### 用户投影和后续边界

沿用 availability、partial、recoveryReadiness，补充解码失败、不支持编码及来源变化诊断，不新增实验状态机。列表区分压缩损坏与运行环境不支持，未核实的零计数显示 u?；错误返回保留原错误原因。

正文成功解码后仍执行已有完整检查、Recovery 和 TaskCase 规则。压缩不降低证据等级，解压成功不证明起点可恢复或任务验收通过。

本批不将历史读取迁到额外 app-server，不把 thread/read 投影当作完整原始证据。共享历史、非本地来源、附件依赖及新增关键事件语义应单独评估，不在这次格式兼容中声称全部支持。未知事件沿用既有诊断与原始证据保留行为；语义兼容性不是压缩兼容测试的结论。

## 备选方案

**只增加后缀**：遗漏详情、脱敏和冻结，拒绝。

**在 Codex 原目录批量解压**：会改变用户数据并与上游 writer 和维护竞争，拒绝。

**整份载入内存或外部解压程序**：增加资源占用或部署依赖，使用有界流式读取与 Node 内置解码。

**完全依赖官方 API**：服务生命周期和原始证据完整性不同，留作独立评估。

## 影响

涉及历史端口的可选字段、Codex Pack、共享读取与冻结及 TUI 投影；TaskCase v1/v2、当前 Runtime 和 CandidateRun 协议保持兼容。未修改门禁和覆盖率阈值。

来源读写的编码责任统一，但解码资源预算不表示支持任意大小或任意第三方 Zstandard 字典。真实恢复和候选测试仍需要原始输入、起点和既有运行授权。

## 验证

生成非敏感明文/zstd fixtures，覆盖索引旧路径、同胞优先及 ID 拒绝、压缩与明文冻结身份及字节相同、脱敏、receipt 拒绝变化、损坏与截断、串联/skippable 帧、校验和、内容长度、解码预算、UTF-8 跨块、取消及并发名额释放。路径用例验证跨根拒绝；Windows 无创建符号链接权限时单独标明该子用例未执行。

最低 Node 和当前 Node 均运行编译后的新增测试；既有 Codex、Claude、冻结、TUI 测试以及 npm run check 验证回归。本机历史样本只做只读导入检查，不提交原始用户会话、不调用真实模型；夹具、实样本导入及真实 Runtime 结果分别报告。
