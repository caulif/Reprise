# 决策：Agent 关闭等待收尾，精确编辑匹配错误允许纠正

状态：accepted

## 问题

调用超时可以先于 Provider 底层执行返回。若 Session 关闭只发送取消，不等待正在执行的工具与审计收尾，工作区释放可能与后续写入交错。精确编辑的原文缺失或匹配不唯一发生在写入前，应给模型纠正机会；普通工具异常不能因此一并降级。Session 缓存的取消也不能吞掉取消回调的审计故障。

## 决定

Session close 与 cancel 共用一次收尾 Promise，首次关闭决定唯一终态，先中止会话信号、取消 Provider，再等待其 waitForIdle（若提供）并追加唯一的会话终态。并发关闭调用等待同一结果，包括失败。Provider 若有取消后仍在执行的工具或审计，必须提供 waitForIdle，确认它们已收尾；没有后台副作用的 Provider 可省略，不要求一个永不结束的纯文本 Promise 返回。

workspace edit/write 在执行开始检查取消；原子写接受可选 AbortSignal，在临时写入前及目标 rename 前检查。journal before 已落盘后取消仍写 failed 配对；已开始的文件系统操作不能撤销，关闭等待真实 idle 后才能释放工作区。

只有 edit 的 oldText 缺失与不唯一两种无副作用匹配前置失败使用既有 ToolPreconditionRejected 通道（edit_match）。错误仍审计并作为原生工具错误返回模型，后续纠正成功可正常完成调用。文件系统、journal、工具审计、完成回调等真实故障仍致命，不按消息文本或错误名称识别可恢复性。

RoleSessions.cancel 仅忽略已由 get 接收的创建失败；实际取消回调失败原样传播，同时移除该缓存项。

Pi 的收尾 flush 可免于重复抛出已从 append 传播的同一审计失败，但新队列中的失败必须传播；审计故障仍保持 sticky，后续模型调用的门禁检查不会忽略它。并发 flush 对仍未完成的同一任务共同等待，任务完成后才移出队列，避免关闭越过被另一次 flush 取走的审计。

## 备选方案

**取消后直接释放，或把全部工具错误降级。** 前者允许副作用越过工作区生命周期，后者会隐藏真实持久化失败，不采用。

## 影响

关闭可能等待工具收尾，失败会传播给调用方。取消不能撤回已提交给操作系统的 rename，也不撤销任意 shell 外部副作用。工具执行并发与默认限额不变。

## 验证

实际 Pi 离线流覆盖两种匹配错误后成功纠正；暂停 journal before 后触发超时与重复 close，证明 close 等待工具收尾、目标内容不变、failed 与 before 配对、Session 终态最后写入。已取消工具不开始写入。缓存取消覆盖创建失败和回调失败两种路径。没有改动模型费用开关、工具并发策略或 shell 超时分类。
