# 决策：覆盖率作业的墙钟预算

状态：accepted

## 问题

串行覆盖率 CI 连续在 30 分钟取消，仍停留在原有报告与所有权测试附近，尚未执行到新增 Runtime 测试。普通三平台测试已通过，不能据此认证覆盖率测试也通过。同机 Node 22.19.0 的基线与当前版本代表性文件耗时接近；完整覆盖率还发现 Node 22 向冻结环境写入 NODE_V8_COVERAGE 的独立启动错误，必须修复而非用超时掩盖。

## 决定

仅将 coverage 作业的外层墙钟预算从 30 分钟调整为 45 分钟，以便串行测试执行到最终断言和阈值检查。保留并发 1、完整测试集合、原覆盖率阈值、临时目录守卫与 all-checks-passed 聚合条件。产品和测试内的超时不变；任何测试失败仍使作业失败。

## 备选方案

**继续重跑同一预算**：已重复取消，不能解决稳定出现的预算不足。

**改为并行覆盖率**：会重新引入既有浏览器资源争用风险，不采用。

**降低阈值、跳过用例或允许失败**：会失去门禁证明，不采用。

## 影响

较慢的执行节点可以使用更长的有限预算，不代表执行节点差异的根因已确认，也不保证测试必然通过。普通测试和审计作业不变。Node 的冻结环境问题在进程边界修复，不能以延长作业预算替代。

## 验证

同批更新 CI 预算反向回归：将 coverage 作业预算改回 30 分钟或移除聚合依赖时自动失败。同批新增冻结环境反向回归：设置宿主 NODE_V8_COVERAGE 后启动子进程，修复前在 Node 22.19.0 抛出不可扩展对象错误；修复后检查原对象未变、未选择的配置未继承、显式配置仍保留。运行源码 build、相关测试和 npm run check；完整覆盖率及远端聚合门禁必须另取得成功结果。参见[开发验证](../../development.md)与[Linux CI 并发决策](2026-10-06-linux-ci-test-concurrency.md)。
