# 决策：固定身份轻列表与 Recovery 有效总预算的组合边界

状态：accepted

## 问题

固定 Experiment 身份、轻量历史列表、延迟 Harness 初始化与分段截止分别成立，但组合后仍可能重新遍历每个实验的冻结附件，或把有效 Recovery 总预算延迟到连接探测后才施加。上游分段计时器与本轮 writer 接纳顺序必须同时保留。

## 决定

列表用 metadata reader 校验固定 TaskCase 描述身份，继续保留内容冲突诊断，但不读取绑定附件、不发完整验证 receipt。当前固定绑定的 `taskCaseFilesVerified: false` 明示该边界；所选实验详情用完整 reader 验证，成功才置 true，失败保留原 run 和具体诊断。使用任务和重比仍须完整验证，不能根据轻列表安装可信 TaskCase。

Recovery 继续先取得 writer、记录初始化 attempt，再发布 activity 并延迟构造 Agent。整体截止由上游分段计时器执行，开始时采用显式 timeout 或共享默认值；有效配置完成不可变绑定后、真实 probe 开始前，按该快照的 recovery.operationTotal 重设剩余截止，扣除自初始化开始已经消耗的单调时间。同一 AbortController 贯穿操作，到期同步拒绝，所有退出路径取消计时器后再聚合清理。

内置 Recovery 的有效整体预算采用同一次构造所用 recoveryBudget.callTimeoutMs，与上游 workflow 的自定义总预算语义一致。显式 timeout 与已绑定 operationTotal 不同则在 probe 前拒绝冲突，不静默改变持久化事实或执行条件。没有配置绑定的自定义 Port 仍使用显式/默认总限，不把其单次 timeout 猜成总限。

## 备选方案

**每个实验都完整读取冻结附件。** 会使身份检查重新绕过轻列表的职责边界；完整验证保留在详情和使用入口。

**先构造模型以取得预算，或等探测结束后重设计时器。** 前者破坏 writer/attempt 接纳顺序，后者允许探测跨过已经记录的有效整体截止。

**显式 timeout 静默覆盖快照。** 记录与执行会分叉，选择明确拒绝冲突。

## 影响

现有 case、事件和报告字节不迁移；分页 v2 增加可选文件验证状态。固定身份格式并不等于已校验全部文件，legacy 的历史身份仍不补认证。配置绑定通知增加同进程类型化 configuration 参数，不新增不可信读取边界。

## 验证

真实离线双 run 夹具篡改同长度冻结附件：列表保持未验证，详情和重比拒绝且不初始化模型；替换描述时不展示错误标题。可控单调时间与计时器覆盖配置绑定前已过期、探测期间到期和显式预算冲突，检查失败记录与 writer 可重新取得。另保留默认超长分段计时器、启动生命周期和原模型输入/报告归属回归；不调用付费模型。
