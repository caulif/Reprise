# 决策：以语义、身份和范围判断任务计时

状态：accepted

日期：2026-10-17

## 问题

原生整轮时间已经进入事件，但候选统计只检查结算事件，因而退回 Host 时间差。比较同时用产品相同和字段同名代替边界证明；未结束尾巴不区分初始化和真实活动，完整记录也可能因无关尾巴被降级。

## 决定

Runtime 首先定义带版本和稳定提交/轮次/结果身份的逐轮计时，Pack 映射原生协议，Host 只投影声明及冻结事件。Claude Code result 的用户消息身份可恢复旧日志关联，原生 API 时间不替代整轮时间。重复不重复计入，无法唯一绑定及冲突保留诊断；缺失结束时间不能用下一轮启动补造。累计字段只有在有明确聚合契约时才能拆分，未知累计格式不猜。

Claude Code 的 duration_ms 从运行时轮次时钟启动计到 result 生成，因此规范边界命名为 runtime_turn_clock_to_result。原生实现将 frame 接收、输入处理和命令队列延迟另外记录，不能把提交身份绑定误当作从接纳开始计时的证明，也不能宣称该值包含全部排队等待。

计时事实以可选第 2 版字段保留语义、范围及初始化尾巴统计，兼容旧持久化值。失败/中止的已知投入保留但不认证成功。部分记录和并行累计不默认声明墙钟下界。

比较采用带原因的四态，保留旧布尔字段。产品名不参与判定，同名字段不单独证明可比。完整、同语义同边界且有 Host 可审计同任务范围才可比较；完整但范围未知仅供参考。Agent 不能用自由描述认证范围。当前默认 session_record 不因共享 caseId 强制变成 selected_task。

## 备选方案

**继续按产品相同判断。** 实现简单，但同产品也可能起止不同，跨产品也可能有规范同口径，因此不能作为判断依据。

**用最近结果或下一轮启动补齐。** 能提高表面覆盖，但迟到、多轮和人工等待会产生错误绑定及虚构耗时，因此拒绝。

## 影响

日志可离线重放，不要求付费重跑；旧报告原事实不改写。部分历史仍有不可恢复的真实缺口，必须显示限制。当前规则和代码入口见[任务执行计时](../../architecture/task-timing.md)。

## 验证

计时投影与 Claude Runner 的离线测试覆盖原生绑定、迟到重复、冲突、会话错配、初始化尾巴、真实活动缺口、失败/中止、并行累计、旧格式和同范围不同边界。逐轮契约反向用例拒绝累计计数器。完整范围缺失时测试必须保留 reference，不能为了显示快慢强制可比；源码构建后执行项目检查。
