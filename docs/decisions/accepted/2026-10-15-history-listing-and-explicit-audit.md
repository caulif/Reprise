# 决策：历史列表延后完整输入审计与空间统计

状态：accepted

## 问题

首页和历史分页原先都先读取全部实验，重建每个实验的模型输入及附件，并同时对整个数据目录和各实验分别递归统计空间。页面只需要任务、运行终态及报告归属，输入审计和快照遍历扩大了读取量；一个条目的 I/O 故障还会使整页失败。

## 决定

历史查询的 v2 列表协议明确 `schemaVersion: 2`、`storageSizeStatus: not_collected`；空间数值缺失，不用零冒充已统计。实验投影以 `modelInputAudit: not_checked` 表达未执行完整模型输入审计。列表仍校验日志提交前缀、record/attempt 身份与报告 owner/hash，不从未检查的附件推导完整性。

列表中的冻结任务校验 JSON schema、owner 与内容描述身份，但不读取全部绑定文件，`filesVerified: false` 明确文件未检查。进入任务详情时重新调用完整 TaskCase reader；只有此后才能使用任务。进入实验详情时只重建选中实验的完整模型输入，原输入、缺失附件和 hash 故障继续由既有 reader 判断。异步结果与原导航 token 绑定，过期结果不写当前页面。

存储统计是独立显式操作，返回 collected、bytes 和采集时间，符号链接/junction 不穿越。旧 `readLocalHistory` 保留完整审计与空间统计用途；首页、历史列表与分页使用轻量查询。条目读取并发最多八个；一个条目的系统 I/O 故障保留 unknown 和安全错误码，未知程序错误继续抛出。parser 的有效前缀诊断显式投影，不把前缀当作完整日志。

## 备选方案

**继续每次全量审计**：可以取得输入完整性，但列表不需要这些附件；保留为明确的审计接口，避免页面刷新隐式承担全部成本。

**新增数据库或可信缓存**：当前证据只要求分离查询职责与约束读取量，不足以证明需要第二种持久化来源。本批不引入派生索引；每次仍检查现存提交事实。

## 影响

查询协议新增明确版本和未采集状态，CLI 消费方应检查版本，不能把缺失数值当作零。旧磁盘数据、事件、发布及模型输入协议不迁移、不重写。列表显示已提交运行结果不代表完整输入已经审计；文件损坏在选中详情/使用任务前仍必须被拒绝或诊断。

取消页面导航不取消已经开始的磁盘读取，但其结果不能回写过期页面。列表仍逐个读取实验的日志元数据；无持久化索引，因此没有与实验数量无关的耗时承诺。空间结果只表示采集时观察到的字节，不是跨并发写入的原子快照。

## 验证

确定性逆例拦截实际文件读取，证明列表不读取模型正文附件或遍历快照；选中详情执行输入审计，损坏附件继续报告不完整。冻结文件损坏可出现在标为未校验的列表中，但完整 reader 拒绝使用。单条目 I/O 故障与不完整尾行在其他健康条目旁保持可见，读取不改原始日志。

在同一 Windows/Node、同一离线合成数据上测量 10/100/1000 个实验的首页、第一页、翻页、详情、完整审计和空间统计；每项至少五次，记录中位数、最慢值、I/O 和内存局限。数据规模和测量结果另列开发文档；不把时延阈值加入门禁，不运行付费模型。
