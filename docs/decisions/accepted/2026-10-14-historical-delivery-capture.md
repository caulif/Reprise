# 决策：历史交付增补，精确终点与用户替代基准

状态：accepted

## 问题

日志静态提取可以确定部分文本补丁，不能重建任意二进制或子代理工作树。合法空清单不代表历史没有交付；恢复任务起点也不等于冻结了历史终点。将用户选择的接近版本标成日志重建，会错误归属模型成果。

## 决定

保留现有历史 manifest v1；v2 为 Host 采集的独立交付，区分捕获文件、精确 Git tree 与用户指定替代品。来源记录包含 case/source 身份、选择依据、捕获时间和内容 hash；替代品保存用户选择与原件状态，未核实不自动声称原件缺失。捕获文件只证明选定字节，不认证它就是首次历史原件。

使用 `historical-deliveries/<caseId>/<selectionId>/` 保存不可覆盖目录；`SELECTED.json` 是操作者通过捕获命令明确选择的版本指针，绑定 manifest hash。再次选择建立新目录，不覆盖 case、旧交付或旧 attempt。原来源定位仅在本地 receipt 中保存；模型与发布使用逻辑路径、来源身份和选择依据。

新 Comparison attempt 优先读取显式选择，校验绑定、字节与 hash，再物化自己的 finals。损坏或错绑选择直接失败，不回退旧空清单或当前用户目录；没有选择时沿用原有 v1 提取/派生逻辑。v2 manifest 另提交为实验 artifact，并追加 `comparison.historical_delivery_prepared`，工具读取仍走既有请求审计。旧报告恢复不查询当前 SELECTED。

替代品身份另投影为 Host replay 条件，说明历史运行指标仍属于原会话，不将替代文件归属给原模型。该事实随正式请求与报告事实持久化，不只依赖模型在正文主动解释。

Git 只接受完整 commit ID，读取指定 tree 和 blob；禁用隐式拉取、替换对象与继承的 Git 定位环境变量，不修改原仓库。批量读取 blob 并校验 Git object ID，避免逐文件启动进程。完整树超过文件/字节预算、Windows路径冲突、symlink/gitlink 或未解析 LFS 时失败，不以部分 changed files 冒充完整终点。不自动联网、安装依赖或执行历史命令。

终点材料位于 Host 的独立目录，不加入 Recovery/Controller 工作区。沿用既有任务前 Git 封存规则；本变更不扩大任意 Shell 的隔离保证。Recovery source 中已有结果线索的起点识别仍由现有恢复流程承担。

预览、发布、渲染 catalog 与来源标签均接受新增来源；替代品明确标为非历史原件。Git 源码链接在预览和发布时按原始字节复制，不解析或改写源码，也不递归加载 import、CSS URL 或 HTML 资源：完整源码树不保证包含构建产物。按需渲染仍走受控渲染工具，其他历史网页交付保留现有资源打包行为。发布仍走现有报告链路，不另建生成器，也不借新增材料契约更改报告样式版本。

完整 Git tree 不是一组已交付的独立网页：不在准备阶段自动截图其全部 HTML/SVG 资产；Agent 可通过受控渲染按需核验。完整来源 catalog 保留全部文件，初始导航优先对应候选改动路径。旧 shell 遇到新 Git 快照时，只展示最多32个仓库来源与32个其他来源，避免数千条路径进入报告；这不改变旧来源报告的投影，新的报告形态另按报告契约演进。

过程导航增加历史/候选事件的完整索引、固定页、原始载荷路径与相邻记录。预览截断和完整索引覆盖范围明确区分，相邻记录不是调用配对证明；无命中不能证明外部从未执行。新增导航由已冻结事实确定性生成，不增加模型阶段。

## 备选方案

**只重跑静态提取器或寻找当前同名文件。** 无法解决二进制/副代理完整终点，也可能把后续版本冒充原件。因此静态提取保留为辅助来源，文件与提交捕获要求明确身份和选择依据。

## 影响

采集是本地显式操作，不调用模型。一次选择固定一个完整基准；多终点之间不按修改时间推断优先级，操作者需明确选择。旧输入保持兼容，旧报告不会因新选择改变。

## 验证

回归覆盖空清单增补、替代身份、篡改/错误绑定、路径拒绝、二进制、Git dirty 与 export-ignore、真实 comparePersisted 入口和预览/发布文件。Codex 静态解析增加有限等价包装并升级提取器版本，动态或夹带写入仍降级，历史代码不执行。
