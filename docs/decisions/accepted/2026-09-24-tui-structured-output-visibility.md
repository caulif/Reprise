# 决策：模型过程正文按共享结构化协议识别

状态：accepted

## 问题

TUI 展示模型可见过程时，结构化最终回执会与已投影的完成事件重复。仅凭 JSON 的 `type` 或 `status` 字段隐藏正文，又可能吞掉未知但真实可见的模型内容。

## 决定

Controller 与 Comparison 原有 TypeBox 回执 schema 移到 core 供代理和过程正文过滤共用，Recovery 继续使用既有 core schema。代理接受的字段和验证规则不变。TUI 只隐藏通过对应 `Value.Check` 且没有未知额外字段的完整回执；无法识别的 JSON 保留原文。已知回执的结果事实由结构化完成事件投影，TUI 不伪造模型推理。

## 备选方案

**按字段名识别。** 仅检查 `type` 或 `status` 会误隐藏未知的模型正文，因此不用作隐藏依据。

## 影响

不改变事件、磁盘格式或模型请求。回归覆盖已知回执去重、未知 `status`/`type` 正文保留和结构化完成事件可见。

## 验证

运行 `npm run check`，其中的过程正文测试覆盖已知回执与未知 JSON。
