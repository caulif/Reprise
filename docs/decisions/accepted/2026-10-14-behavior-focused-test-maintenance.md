# 决策：按行为与隔离边界维护测试

状态：accepted

## 问题

历史会话测试把开发者当前仓库作为历史 cwd，导入时递归探测真实目录；恢复数据集在一个测试中重复执行相同内容与扰动，符号链接权限不足会跳过整个父测试。旧流程、源码形状检查与验收索引还可能掩盖当前默认 Comparison 装配缺少联测的问题。

## 决定

- 历史 cwd 使用临时夹具。实际文件系统、Git 与持久化边界仍通过集成测试验证。
- Recovery 数据集全部记录经过 schema 与逐文件 hash 校验；共享工作区恢复按移除样本 ID 后的不同内容和扰动执行。pack 标签不参与此测试，不宣称产品 Runtime 覆盖。每种组合独立子用例，权限不足只跳过对应符号链接用例。
- 默认 Comparison 从生产工厂出发，替换 Pi 模型响应和截图 renderer，保留工具装配、实际 generation 输入审计、Store、发布与离线重读。缺少预览、修订后过期预览及取消必须拒绝发布；重新预览当前稿后才能成功。
- 重试协议使用 Node 虚拟定时器验证退避及取消，保留真实截止回归。Promise timers 通过标准模块对象调用，使测试能控制原定时器，不增加生产专用测试开关。
- 依赖边界检查继续保留；删除只锁定内部文件拆分与辅助函数名的检查。历史验收矩阵归入[测试覆盖索引](../../../test/README.md)，不作为能力通过证明。
- 保留旧 Comparison 端口及历史日志的兼容回归，沿用[自主 Session 决策](2026-10-11-comparison-autonomous-session.md)。不通过降低覆盖率阈值或默认跳过旧契约来减少成本。

## 备选方案

**仅提高并发或裁剪默认测试集合。** 提高并发不能消除对真实工作区的依赖；直接删掉旧流程测试会破坏仍受支持的兼容契约。把全部慢测试移出日常门禁也可能遗漏文件系统与进程边界，因此先消除无关扫描和重复工作，暂不新增测试筛选规则。

## 影响

测试数量变化不作为优化成功指标。check、full 与 CI 继续运行完整默认集合；fast 仍是门禁子集而非独立单元测试集合。快照、脚本化模型和模拟图片不认证真实模型语义或浏览器视觉质量。产品状态机、持久化协议和默认运行预算不变。

## 验证

先构建，再运行受影响测试，最后执行 npm run check。新增发布联测包含缺预览、过期预览与取消反例；虚拟退避在截止前拒绝下一次请求，并验证等待期间取消。覆盖率沿用现有阈值，测试结果逐子用例报告环境跳过。
