# 决策：Linux 预览浏览器启动与 CI 诊断

状态：accepted

日期：2026-10-06

## 问题

Ubuntu CI 的真实对照发布测试曾在等待 DevToolsActivePort 15 秒后失败：子进程仍存活、profile 存在、端口文件缺失、stderr 为空。同一文件后续真实预览成功。原日志没有实际启动路径，不能据此断定 snap wrapper、并发资源争用或浏览器缺失。

## 决定

- Linux 已安装 Google Chrome 时优先 `/opt/google/chrome/chrome` 原生二进制，再尝试原有系统和 PATH 候选。避免同一浏览器的 wrapper 启动行为变化；不删除 Chromium 或 snap 候选。
- CDP 会话诊断记录实际选中的可执行文件，启动超时也携带该路径。生产等待仍为 15 秒，不重试来延长预算。
- Linux CI 在原测试 lane 结束后独立运行真实 CDP 诊断：比较可执行文件的版本与 `Browser.getVersion`，创建并关闭真实页面 target，再释放浏览器。
- 该步骤是非阻断诊断，便于区分并行测试故障与独立启动故障；原 lane 和真实预览、版本绑定、发布检查仍然阻断。诊断成功不证明原故障已经消失，也不扩大 Linux 已验证范围。

## 备选方案

**提高生产启动超时或失败后无限重试。** 没有证据证明等待更久能解决故障，会扩大预算并掩盖启动异常。

**断定 snap 故障、删除所有 wrapper 候选。** 原日志没有实际启动路径，结论缺乏证据，也会移除原本可用的浏览器安装。

**将独立 smoke 设为新的发布门禁。** 与原真实预览检查重叠；本轮先保留非阻断诊断，以获得区分启动环境与并发争用的执行证据。

## 影响

Linux 安装原生 Chrome 时启动路径优先级改变，其他平台及 fallback 保持原规则。诊断记录增加实际可执行文件路径，未改变预览内容、版本绑定、发布条件或生产启动预算。Ubuntu 原超时原因仍未确认，需要结合下一次 CI 的原 lane 与独立启动结果判断。

## 验证

原生候选顺序和启动超时包含可执行路径由现有浏览器测试覆盖。诊断脚本的 `--self-test` 证明缺失 CDP 版本和可执行文件/CDP 版本不匹配必须失败。真实 CDP 诊断及原测试 lane 的 Ubuntu 结果作为后续执行证据；本地 Windows 检查不能替代该证据。
