# 决策：运行记录摘要由应用层投影

状态：accepted

## 问题

运行记录页需要展示任务标题、执行工具和模型。旧列表只返回内部 ID，若由 TUI 逐行读取 `case.json` 和运行记录，会重复扫描磁盘，并让只读页面承担持久化解析和损坏数据判断。

## 决定

`readLocalHistory` 从经 `Value.Check` 验证的 TaskCase 和 RunRecord 生成可选展示摘要。读取时按 `taskCaseId` 关联一次；刚结束的结果使用同一组事实生成摘要。摘要不写回磁盘，不改变 TaskCase、RunRecord 或事件格式。缺标题时界面使用短任务 ID，缺运行字段时保留未知状态；解析损坏不能被标题兜底掩盖。损坏的已发布任务单独计数并在历史任务页显示诊断，健康任务与运行记录继续可用。

结果页、历史页和首页状态继续使用共同的事实投影。TUI 只保存页面选择、滚动和展开状态；准备、执行、比较及报告发布仍以应用层结果和事件为准。

## 备选方案

**由 TUI 按行读取原始文件。** 页面会重复扫描目录并自行处理 schema 和损坏记录，违背只读投影边界。

**把摘要持久化到实验目录。** 会引入可与真实任务和运行记录分叉的新状态，还需要迁移旧记录。

## 影响

运行记录 DTO 增加可选字段，旧数据及无对应 TaskCase 的记录仍可读取。摘要只方便识别，不作为新状态或比较依据。损坏文件需明确显示诊断，不能将其悄悄视为空列表，也不能阻断健康记录。应用层历史读取与 TUI 列表、详情需同步维护。

## 验证

应用层历史读取和当前结果转历史的测试覆盖标题、模型及缺失数据；TUI 测试覆盖列表和详情的状态一致性。无真实 Runtime 调用，无 on-disk 迁移。
