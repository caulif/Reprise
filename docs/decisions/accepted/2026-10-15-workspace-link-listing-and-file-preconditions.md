# 决策：目录链接作为条目，文件前置拒绝允许纠正

状态：accepted

## 问题

Controller 复核含 pnpm 链接的项目时，普通目录列表遇到一个链接就抛出未知异常，Host 将其升级为致命工具失败并取消独立并行读取。目录中的链接存在本身不表示遍历失败；但列出链接不能授予读取或写入其目标的权限。

## 决定

共享 workspace 工具的递归遍历将链接输出为 `symlink <path>`，不解析目标，不进入链接，继续列出其他条目。Windows junction、外部目标、失效链接及循环都使用相同规则。find 返回链接路径本身，grep 只搜索普通文件。请求路径和祖先的现有包含性检查继续执行；受控路径直接经过链接仍被拒绝，原有 unrestrictedRead 的外部读取授权不扩大。

明确的链接路径拒绝与非普通文件目标在操作前分别抛出类型化前置拒绝；超出文件工具 UTF-8 字节上限的 edit/write 也使用参数拒绝。Controller 沿现有结构化 rejected 结果返回 code、message、retryable；Recovery/Comparison 沿现有原生工具错误通道反馈，允许纠正后继续。既有不存在/不可读反馈保持不变。不得按异常文本识别可恢复性，不将任意 filesystem errno、未知异常、完成回调、事件审计、journal 故障或写后越界完整性检查泛化为前置拒绝。取消和致命错误仍走原有 Provider 传播路径。

不把快照的可重建依赖排除规则套到目录查询。当前不存在通用的文件工具忽略策略；快照规则需要 lockfile 等重建证据，Git dirty 检查的依赖过滤也不定义模型可见目录。套用会隐去任务可能需要调查的文件。维持既有深度/条目上限，依赖目录按普通目录列出，链接一律不递归。

## 备选方案

**跟随链接、静默跳过或普遍降级异常。** 跟随所有链接会扩大读取边界且可能产生循环；静默跳过会隐藏目录事实；将所有工具异常转换成结果会掩盖审计与完整性失败，均不采用。

## 影响

此修改不声称解决并发外部进程替换目录的 TOCTOU，也不增加 OS 沙箱。批量补丁通过全量预检后，应用阶段的任何前置拒绝均转为致命失败，避免部分修改被误当成无副作用拒绝；Host 日志路径上的链接和 journal 回调抛出的类型化异常仍致命。

cleanup capture 使用环境 fingerprint 与 snapshot 链路，不使用工具 listTree。本次不改收尾时限、快照策略或释放条件；独立的捕获超时不能因目录工具回归通过而宣称解决。

## 验证

新增目录条目类型，find 同步去除类型前缀；无 on-disk schema 迁移。回滚代码即可恢复旧行为，但旧版本仍可能因目录链接终止。测试覆盖真实 Windows junction 的内部 pnpm 布局、外部/失效/循环目标、链接访问和写入拒绝，以及离线实际 Pi SDK 中三角色纠正、独立读取完成和致命故障停止。离线模型流不是线上模型或完整真实 Controller 任务验收。
