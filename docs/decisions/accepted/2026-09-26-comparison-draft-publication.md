# 决策：Comparison 草稿提交与版本发布

状态：accepted

## 问题

模型既维护整页 HTML 的 Host 标记，又在长调查后交回唯一 JSON 信封。历史失败分别落在标记、必需槽、证据短引用和末尾空输出；增加 JSON 修复轮不能消除这些独立脆弱边界。最新一次草稿通过 Host 发布校验且有相同 digest 的成功预览，仍因末尾空 JSON 未发布。

## 决定

- 新 Comparison 使用 `submit_comparison_draft` 提交任务相关内容槽。Host 即时按 schema、HTML、证据、媒体和 Host 区域校验并生成完整 `report.html`；被拒绝的提交不替换上一个有效草稿。生产 Agent 的文件写入工具仅可改工作笔记和 scratch。旧自定义端口保留整页写入与最终校验兼容，旧 attempt 不自动迁移。
- 发布依据是最近一次有效提交的草稿 digest、catalog revision 和同版本成功预览；发布前再次读文件并校验。审阅调用正常结束但最终文本为空时可发布此冻结版本，并保留审阅结论缺失的审计事实；取消、模型/网络失败、未预览、无效草稿或版本变化不得转成成功。
- 新流程合并理解和调查为定向调查，随后提交、审阅。首轮利用 Host 索引，追查会影响任务结论的问题；阶段事件记录耗时、请求、工具、压缩及预览次数。旧四轮 JSON 修复只供旧端口兼容。
- Comparison 将已分类的认证、限流、网络和上游服务错误标为 `provider_failure`，保留原 `kind`；草稿、预览及发布错误分别使用 `draft_invalid`、`preview_failed`、`publication_failed`，避免统一归为 `agent_failure`。
- 旧失败 attempt 默认只能离线复核。显式 `recover-comparison --publish` 必须重校验冻结事实、预览事件和当前版本。发布前记录绑定 attempt、草稿、状态及正式页面摘要的准备事件；同版本中断重试须核对已有页面摘要，拒绝覆盖其他正式报告；成功追加恢复事件，保留原失败审计。

## 备选方案

**继续重试末尾 JSON。** 已有有效草稿仍会被独立信封门槛丢弃，也不能修复整页标记或证据引用错误，因此不采用。

## 影响

报告的机械完整性和发布权从末尾模型信封移到 Host。审阅文本为空不代表报告内容已由人确认；真实模型或上游服务仍可能失败。

## 验证

回归覆盖空收尾、无效内容、未预览或版本变动、取消/服务失败、旧报告保留与离线恢复。真实文本和 HTML/SVG 任务的耗时、质量验收仍需显式 opt-in 执行。
