# 决策：Comparison 推荐绑定发现的实际输出支持范围

状态：accepted

## 问题

数学目标与中间计算一致，并不能证明最终交付经过全部变换后仍满足任务。仅要求结论和未知段落存在，会允许正文一边承认关键关系未测，一边以该关系支持推荐；合法引用和非空免责声明无法阻止这种范围越界。

## 决定

- 当前 findings 工具要求每个双侧 observation 声明 `supportBoundary`：被检验关系、范围、`delivered_output` / `intermediate_only` / `unavailable`、覆盖实例与未检实例。交付输出至少有一个覆盖实例，不可得不能声称已覆盖；自述或不可得方法不能声称验证交付输出。源码和数学复算可以检验实际输出链，不能凭方法名称自动认证。
- 当前草稿工具要求 `decisionBasis`、`conclusionScope` 与 `findingDispositions`。每个当前 finding 恰好分配一次依据、边界或不决定选择的角色并解释；依据 ID 必须与依据角色一致。生产有 findings 的 completed 判断至少有一个依据；没有可用依据可以正常提交 insufficient_evidence 与 undetermined。
- 依据及边界角色中任一 observation 缺少支持范围、只覆盖中间结果、不可得或存在未检实例时，不能声明 supported_in_scope。有条件或未定结论仍可结束，不强迫继续调查或制造赢家。Host 在普通主文按 finding 保留任务 criterion、涉及侧及局部交付支持或交付结果未确认的性质；同性质的双侧合并表述，不逐 observation 重复技术目录。模型声明的 decisionBoundary 全文仍在主文，必须保留真正改变选择的未知。完整关系、范围、已检查及未检实例转义后以自然语言进入 details，不重复阶段枚举和 JSON 字段，不截断、不自动判断哪条未知重要；完整机器字段保留于现有 findings artifact。所有自动附属主文和 details 继续计入原 250/600 与 400/1000 限额。
- 这些都是模型声明与机械一致性规则。Host 不判断自由文本真实性，不认证覆盖完整性，不按任务关键词选择赢家，也不证明模型将关键 finding 正确归类。独立语义验收继续检验完整实际输出链及推荐是否超出依据。
- 基础发现持久化和旧 typed 提交字段保持 optional，新 live 工具必填；旧记录按原契约读取，不补造范围。新增支持字段会写入新 findings artifact，扩展 on-disk 契约。兼容方向是新 reader 读取旧记录；旧 reader 的 additionalProperties 校验可能拒绝新记录，不能保证向后版本读取。
- 引用归属或缺失拒绝返回具体字段位置、side、finding/question ID、提交短引用的已知归属或 not_found，以及最多 12 个相关短引用的目录元数据和省略数量；额外目录导航仍受原阶段资源限制，可能不可执行；不能反复重试被拒读取，已有观察与有限目录不足时须保留未知并限定判断。反馈不包含私有路径、原始来源身份或整份发现正文，不自动替换引用、side 或 criterion，不认证语义。原严格归属门禁、普通工具事件审计和拒绝后状态不变保持不变；目的是让模型依据事实一次修正结构错误。

## 备选方案

**只叠加提示与免责声明。** 不能检查推荐依据，也不能防止重要未知被隐藏。Host 自动分析自然语言或固定任务质量表会把通用 Agent 变成样例规则系统，且不能可靠认证科学和业务语义。采用任务自适配的结构化范围与角色，再保留独立真实语义复核。

## 影响

扩展 live 工具、持久化发现与主文内容契约；不增加报告模型的第二份权威结论，不改变原篇幅、预算、模型或发布绑定。主文保留任务支持边界，细粒度测量目录按需展开；模型不能把真正改变判断的未知仅藏在 details。完整目录超过 details 限额时仍拒绝草稿，不通过截断条目求通过。

## 验证

自动化逆例覆盖缺范围、交付阶段零覆盖、不可得伪覆盖、方法与阶段不一致、遗漏或重复 finding、依据映射不一致、未检边界下声明充分支持、转义和总字数。旧记录与旧直接提交保持可读。先 build，再执行 compiled focused 与项目 check；机械通过不能替代原例和跨任务真实语义验收。

引用修复逆例另覆盖错侧、未知短引用、located 空来源、finding/question 错误位置、目录裁剪与私有字段不泄露；每次拒绝保持此前已接受记录和持久化次数不变。
