# 决策：分离受管进程退出与日志收尾

状态：accepted

## 问题

受管进程的 close 回调已经取得退出码，但完成 Promise 还要等待日志落盘。大量错误输出产生逐行串行 appendFile，导致日志排空慢；取消的 5 秒窗口因此将日志延迟误报为进程终止未确认，并使整个 Agent invocation 失败。旧版同样存在该机制，延长单个终止超时不能消除状态歧义。

## 决定

ManagedProcessSnapshot 增加 `flushing`：根进程及管道已关闭，日志仍在排空。它不是候选状态机的新状态；ManagedProcessSession.running 在 running 和 flushing 时均为真，表示工作区仍被占有。只有 completed/cancelled 才能发布完整日志；真实持久化失败和终止不确定性仍致命。

进程关闭与日志保存分别拥有完成信号。cancel_process 对尚未关闭的进程保留 5 秒终止确认窗口；日志保存使用独立 5 秒等待窗口。日志窗口耗尽返回 flushing，允许 write_stdin 再次等待或再次 cancel；成功结束过的窗口不被永久缓存。真正终止失败与日志写入失败保持故障，不因之后出现退出码而静默成功。

Invocation 收尾不能把 flushing 当作遗留运行命令：最多再等 60 秒保存日志，未完成则报明确日志排空超时并拒绝封存，不能无限等待或提交部分日志。仍在运行的命令必须终止且 invocation 不接受为正常完成。各 Session 并行清理，汇总全部清理结果后再返回。

日志保持既有逐管道 UTF-8 解码、脱敏与截断行为；脱敏后的内容在 64 KiB 阈值或下一事件循环合并写入，finish 强制刷出尾块并等待写入链。整个排队内容仍受既有 16 MiB 上限约束，不添加无界内存队列、不省略正常日志或吞掉磁盘错误。模型可见的 1 MiB 增量缓存同样先收集有界分块，在 poll 时合并，避免每行复制已缓存的全部内容。

## 备选方案

**只延长终止超时。** 仍混淆进程状态与日志状态，积压超过新窗口后同样误判，不采用。

**忽略日志错误或先发布日志副本。** 会接受不完整审计，无法保留真实写失败保护，不采用。

## 影响

增加模型可见的 flushing 状态和工具描述，不增加 Agent 阶段或依赖；只改变收尾与写入方式，不迁移历史材料。

## 验证

针对性测试覆盖延迟日志超过取消等待窗口后恢复、日志未完成的工作区占有和封存阻止、迟到的写失败、真实终止未确认、日志排空截止时间，以及真实子进程的大量重复输出。既有凭据分片、UTF-8、日志容量与 Windows 后代写入取消检查继续执行。

这些测试验证工具生命周期，不等于原完整 Comparison 任务或模型行为验收。没有增加 Agent 阶段、依赖或模型请求额度，也不将 trusted-local shell 声称为操作系统沙箱。旧事件仍可读；旧程序不理解新的 flushing 工具回执，因此运行中会话应继续使用同一版本。
