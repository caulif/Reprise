# 决策：Comparison 统一阶段策略与端口能力

状态：accepted

## 问题

阶段权限原来分散在多层工具包装、模型曝光和 turn 退出判断中，来源工具集合重复维护。应用又按具体 ComparisonAgent 类身份选择 findings 协议，代理或装饰器无法声明相同能力。发布媒体扫描把合法源码引文中的 CSS URL 当成实际资源，甚至改写引文而破坏原文认证。

## 决定

- 用显式工作阶段及单一阶段策略定义允许工具、参数守卫、完成回调和退出条件。生产工具只绑定一次阶段守卫；findings helper 保留实际接受回执和当前绑定的观察状态，不独立决定生产工具权限。资源 tracker 与计量包装独立，不增加额度。旧默认工具曝光保留兼容，严格生产曝光由同一允许策略派生。
- 在 ComparisonAgentPort 上声明可选 requireFindings；启用后统一注册 findings 工具、提供回调、绑定草稿及持久化独立审阅契约，任何端口实现都可声明。未声明的旧实现保留兼容模式；可选 reviewInspectionRequired 保留仅启用全文检查的内置旧模式。工作区写权限同样按协议能力选择。
- 媒体枚举和路径重写复用现有 evidence-quote 保护，不扫描或改写引文正文。引文仍须从注册源字节验证；真实 markup 的外部资源、未注册媒体及路径越界检查不放宽。不新增依赖、持久化格式或模型调用。
- 新独立来源会话接收保存 findings 作为待核实假设及绑定导航，先核实际来源再读作者稿；该顺序不构成完全盲审或语义认证，沿用有界审阅收敛决定。

## 备选方案

**继续叠加包装并各自维护权限，或只隐藏工具。** 前者会保留曝光、执行与退出之间的漂移风险；后者无法阻止忽略允许列表的 adapter。选择一个阶段策略同时驱动三者。

**按 instanceof 或要求装饰器继承内置类。** 这会把协议能力与实现身份绑定，因此选择可选端口声明。

## 影响

保存回执状态和资源计量仍分别归原 helper 与 tracker；未声明能力的旧端口实现保持兼容。媒体修复复用现有引文保护，避免另建 HTML 转义或引用解析规则。不新增依赖、持久化格式或模型调用，资源额度和真实媒体检查不放宽。

## 验证

阶段逆例覆盖强制调用未曝光工具及完成回调、实际回执和绑定驱动退出、参数相关修复读取及预览守卫。发布逆例覆盖本地和外部图片 URL 引文、与注册媒体碰撞的引文，以及真实 markup 仍被拒绝。应用集成覆盖声明能力的非内置类端口取得 findings 协议与持久化审阅契约。Windows 与真实模型验收仍需独立执行。
