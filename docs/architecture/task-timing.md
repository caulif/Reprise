# 任务执行计时

Comparison 的耗时来自 [计时投影](../../src/application/session-timing.ts)，并非 Comparison 分析耗时或候选运行整体跨度。轮次间人工等待不计入轮次累计；并行轮次累计也不是墙钟跨度。来源引用、覆盖和诊断随报告事实冻结，旧发布事实不原地重写。

[Runtime 端口](../../src/core/runtime.ts) 的单轮计时声明版本、语义、起止边界、逐轮聚合方式和提交/轮次/结果身份。Claude Code 从 result 的 `duration_ms` 映射整轮时间，不能代用 API 时间。新 settlement 的原生计时必须与原生提交身份匹配；旧日志用 result 的单一用户消息身份关联已接纳提交及结算，不用最近事件或下一轮起点猜测。迟到、重复和乱序记录可重新投影；冲突时保留诊断，不重复累计。无明确逐轮契约的累计值不能直接计入单轮。

历史完成轮次优先原生整轮时间，其次匹配事件或原生起止时间。未匹配启动只有在冻结记录尾部、后继仅为设置/上下文且没有可见活动时归入初始化尾巴；这只描述记录，不能证明进程没有工作。它在 sessionCoverage 单独保留，不让已完成工作的覆盖变成缺口。用户消息、推理、用量、工具活动或中止均保留为真实未结束工作；不补造结束时间。失败和中止轮次的已知投入可计入累计，但 outcomes 和诊断保留其状态。

计时事实第 2 版附语义、边界及范围；旧无版本事实仍可读取。默认范围是整个冻结会话记录。只有 Host 已有可审计任务选择 identity 与边界引用时，才可传入 selected_task 范围；相同 caseId 或模型自由描述不是证明。当前自动路径不臆造这一证明，因此完整旧记录一般只能参考。

比较状态分为可比较、可参考、记录不完整和无法取得，并保留具体原因。产品名既不证明同口径，也不禁止跨产品比较。只有双方完整、无影响可信度的诊断、相同语义/边界/累计方式且证明同任务范围时才可比较；其它完整记录仅供参考，不计算快慢百分比。重叠区间明确标注，部分累计称已记录耗时，不默认称至少。保留旧 timingComparable 布尔投影及旧字段读取。

决策理由见[语义计时契约](../decisions/accepted/2026-10-17-semantic-task-timing.md)。
