## 项目起点

项目从一个个人用户问题出发：公开榜单和经典基准往往不能代表自己实际使用 Agent 的体验。新模型发布时，用户需要知道它在**自己做过的真实任务**上是否更好用。

因此，项目被定义为 Reprise：从本机 Claude Code、Codex 等 Agent 产品中选择历史会话，在尽可能相同的 Agent 产品、版本、工具与环境条件下，让候选模型重新完成任务；再保存过程事实、产物、成本、时长与异常，帮助用户检查差异。

关键难点是长任务的 human-in-the-loop：候选模型的轨迹与原轨迹不同，后续人类输入不能机械回放。Harness 中的 Controller 应基于原会话证据和当前轨迹，生成同等人类能力下相称的后续输入。

## 时间线

### 2026-08-05：你纠正问题定义，确定产品边界

- 调研需求、可行性、理论支撑与竞品；确认核心定位：**用个人真实历史任务做换模决策，而不是建设通用排行榜、标准评测集或大规模私人题库。**
- 你进一步判断：**任务数量不必很多；一两个高价值真实会话即可服务个人决策。**
- 你明确拒绝把“公平”简化为脱离产品的基础模型测试：**用户实际使用 Claude Code / Codex，产品、内置提示词、工具和版本都是体验的一部分。**
- 你否定了把结果强压成单一分数的方向：时长、成本、token、工具调用等效率数据可直接记录；功能、UI 等质量应展示证据，让用户判断。
- 这一阶段产生的早期分析和路线图已归档至 `docs/archive/2026-08-07/`，仅供追溯。

### 2026-08-06 至 2026-08-07：你在复用与自研之间做技术取舍

- 在“复用还是手写”之间，你选择 **Pi Agent Core + 自有 Harness**，而不是手写完整 Agent Runner。
- Pi 负责可复用的 Agent 核心能力；Harness 自己负责历史会话导入、Agent Product 适配、环境恢复、Controller、运行编排、trace 和结果比较。
- **原历史会话只作为证据，不重新运行；只有候选模型需要在 Runtime 中执行。**
- **运行时应尽量匹配原会话对应的 Claude Code / Codex 版本**，因为内置提示词和工具会变化。
- 候选模型来自用户在相应 Agent 产品中真实配置、可用的模型，而不是简单枚举 Pi 模型。
- 设计风格被持续约束为：简洁、务实、优雅、克制；避免没有第二实现就预先抽象。

### 2026-08-07：你把 Harness 的关键机制落为架构边界

- 你把 Controller 定义为**有能力边界的协作/监督模块，而不是通用人类模拟器**；它决定是否介入、输入什么、何时结束，不暴露原始思维过程。
- **架构采用薄编排层、模块化单体、端口/适配器边界和 append-only trace**，避免过早抽象。
- 环境恢复与人机协作被分离：前者回答“能否在可信副本中运行”，后者回答“当前候选轨迹下人应输入什么”。
- Comparison 只选择值得查看的差异和证据，不伪造绝对质量总分。
- 对 Controller 的讨论参考 mixed-initiative interaction、grounding、scaffolding、联合认知系统和监督控制；整体架构参考端口与适配器、防腐层、事件溯源、能力安全及演进式架构。

### 2026-08-08：你删减复杂设计，补足不能妥协的协议

- 当前文档被整理为 `product/`、`architecture/`、`research/` 与 `archive/` 四层；`architecture/overview.md` 成为跨模块唯一主设计。
- 你主动删减 TaskCase 设计：**保留 `ImportedSession`，但默认把一个历史会话从开始到结束作为一个任务；不引入复杂的任务构建器和人工切分边界。**
- 你将 Environment 的安全边界落为协议：在资源级记录请求状态、恢复状态、恢复方法和置信度；**候选运行只允许在隔离副本中进行；无法安全恢复时直接标记为 `unsupported`，禁止原地运行。**
- **结果与异常拆分**：区分 `RunOutcome`、`StopReason`、`FailureCategory`、`CleanupStatus` 与 `DeliveryCertainty`；避免把完成、预算耗尽、无进展、Runtime 崩溃、输入未送达和清理异常统称为 `failed`。

### 2026-08-08 至 2026-08-09：你选择 TUI，并给报告降级

最小使用流程收敛为：配置 LLM API → 选择 Agent Harness / 产品 → 选择历史会话 → 选择该产品内可用的候选模型 → 检查 Runtime、隔离环境和预算 → 启动比较 → 查看结果与证据。

- 在 TUI 与 Web 之间，你明确选择 **TUI 作为唯一控制面**。
- 运行时借鉴 Claude Code 和 Codex：展示状态、活动、结构化判断依据、最终输入和结束决定，但不展示 Controller 的原始思维过程。
- 你对静态本地 HTML 的判断是：**保留它作为可重新生成的只读报告投影，但不让它进入核心闭环。** 它适合并排查看截图、页面、图表、PDF、diff、指标与证据；它不是运行、恢复、Controller 或 Comparison 的前置依赖，生成失败不得使候选运行失败。
