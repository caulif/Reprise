# AGENTS.md — 文档层

本文只包含写 `docs/` 时才需要的规则。目录模型、权威层级和受控边界的完整定义见[文档结构与路径约定](./documentation-structure.md)。仓库级规则见[根 AGENTS.md](../AGENTS.md)。

## 放置决策树

新增内容前，按顺序回答，第一个「是」决定位置：

1. 它定义实现必须遵守的规则？→ `architecture/`（跨模块语义只进 `overview.md`）或 `product/`。
2. 它记录一个已经做出、且会长期约束实现的选择，包含被放弃的方案？→ `decisions/`。
3. 它描述还没做完的工作？→ `plan/`。
4. 它解释「为什么这样设计」，可以被推翻？→ 长期选择写入 `decisions/`，一次性推导放入 `docs/.local/`。
5. 它是某一时点的审查、走查、体验记录，或已经执行完毕的计划？→ `docs/.local/`，不受版本控制。
6. 它由脚本生成？→ 生成区或产物目录，不手写。

判断不了就不要新建文件：先找现有文档补一节。

## 文档层规则

- **一份事实只有一个归宿。** 别处需要它时给相对链接，不复制正文。发现两处描述同一件事，删掉不是唯一来源的那一处。
- **写当前状态，不写变更过程。** 禁止「原先」「现在改为」「不再」这类叙述；要记录变更过程就写 `decisions/` 或 commit message。
- **不手写清单。** 目录内容、测试列表、事件类型、配置字段一律不在正文复述——它们会漂移。需要清单就生成，或只给目录链接。
- **不写实现状态标注。** 「已实现」「待办」「future」会腐烂；状态由 `progress/MASTER.md` 和代码本身承载。
- **不留推理过程。** 删掉逐步推导、显然分支的论证、测试走查；保留结论、约束和失败模式，理由链到 `decisions/`。
- **强调要吝啬。** 每处都加粗等于没有重点；只加粗改变行为的那一句。
- **术语要具体。** 写「响应字段」「JSON 校验」「ESM 导出」，不写「响应形状」「校验边界」「模块形态」。`契约`只用于调用方真正依赖的前置条件、后置条件和不变量。

## 受控边界

受控路径以[文档结构](./documentation-structure.md#受控边界)的目录模型为准。其余一律不受控，见 `.gitignore`。`tui-audit/frames/` 是例外中的例外：它是 CI 逐字节比对的快照基线，改动 TUI 渲染后必须重新生成并提交。

## 链接与体积

- 仓库内引用一律用相对 Markdown 链接，不写裸文件名，不写绝对路径。链接和锚点由 `npm run verify:docs` 校验，断链即失败。
- 本文与根 `AGENTS.md`、`src/AGENTS.md` 受字符预算约束（`scripts/doc-budgets.manifest.json`）。预算红灯时的顺序是：先搬走属于别层的内容，再压缩本层内容，最后才提高上限并在 `decisions/` 里说明理由。上限是护栏，不是压缩目标。
