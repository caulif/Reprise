TUI 与 CLI 共用编排

第三套调用方，不是第二套状态机。TUI 继续只读投影事件日志。

TUI Intake 翻列表 + CLI recover 另一会话 允许 TUI 看 History + CLI 刚写完的 Case 允许（读磁盘） TUI 正在跑 experiment-A + CLI run 同一 A 禁止 退出码 4 TUI 正在跑 experiment-A + CLI run 新的 B 允许 两个 CLI 抢同一 lock 禁止 不自动抢锁
第一版不要求 TUI 热跟随另一进程的时间线；打开 History 即看见 CLI 产物。

产品非目标仍是「不做 Workflow Engine」。CLI 只是把确认页上的三个动作（选会话并恢复、开跑、读报告）变成可脚本化动词，费用确认改成 --allow-recovery / --allow-run。

身份不要混用

产品会话 ID 只用于发现和 recover。开跑之后只用 Harness 的 case / experiment / run。

SessionRef → TaskCase → Experiment标志
# 产品世界（Pack） --product codex --session 0192ab… 跨产品会撞号，所以 product 必填 --source-path C:\…jsonl 同 ID 多文件时才要 # Harness 世界（冻结之后） --case case-… --experiment experiment-… --run run-…
list 的 JSON 把三项都返回；agent 原样回传，不要自己拼 Windows 路径。

发现与核对

对应 TUI /intake。list 没有 transcript；show 默认也不倾倒全文。

PS C:\work>TTY 人类表
reprise sessions list --product codex PRODUCT SESSION UPDATED TITLE codex 0192ab… 2026-09-01T12:04Z 把登录改成 passkey codex 0192cd… 2026-08-30T09:11Z 修复 intake 光标
加 --json 后是 SessionSummary 页 + cursor，不是这张表的字符串。

冻结资格以 inspect/import 为准，不以列表截断摘要为准。这与 TUI 核对页同一规则。

recover = 冻结 + Recovery Agent

对应选会话后的恢复。不启动候选 Runtime。内部 Pi 费用要 --allow-recovery。

stdout --jsonexit 0
{ "schemaVersion": 1, "ok": true, "command": "recover", "code": 0, "data": { "caseId": "case-7f3a", "experimentId": "recovery-…", "userRecoveryStatus": "partial", "canStart": true, "reasonCode": null }, "next": [ { "argv": "reprise run --case case-7f3a --allow-run --wait --json", "when": "canStart" } ] }
failed 且 canStart=false → 退出码 3，禁止接着 run。缺 --allow-recovery → 退出码 5，不写 Case。

校验通过的 preview 仍自动 accept；操作者/agent 确认的是「要不要花内部模型钱做恢复」，以及下一步「要不要花候选钱开跑」。两段确认拆开。

run 含 Controller；report 读 Comparison

第一版不另设 compare 动词。Comparison 仍在收尾自动跑；--wait 等到投影落盘。

PS C:\work>stderr 进度 · stdout JSON
reprise run --case case-7f3a --allow-run --wait --json # stderr harness preflight ok · isolation copy target turn 1 settled controller send follow-up comparison report.html # stdout 仅信封 { "ok": true, "data": { "experimentId": "exp-…", "runId": "run-…", "reportPath": "C:\\…\\report.html" } } reprise report --experiment exp-… --json
--product / --model 选的是候选 Pack，不是来源会话产品。省略则来源 Pack 的 defaultCandidate()。

信封是唯一稳定调用面

Value.Check。事件类型、TUI 文案、HTML 壳都不是外部 agent 契约。

退出码含义
0ok
2用法 / SessionRef 无效 / 无合法用户任务句
3无法恢复，canStart=false
4writer.lock
5缺 --allow-recovery 或 --allow-run
6前置未完成（无 baseline、Comparison 未落盘）
1未分类

非 TTY 默认 JSON；TTY 默认表。管道里的人若要表，规划里留了是否加 --table 的讨论项。

外部 agent 四步

把这段放进调用方自己的说明即可。不读 ~/.codex JSONL，不点 TUI。

agent 工具调用headless
1 reprise sessions list --product codex --json 2 reprise recover --product codex --session <id> --allow-recovery --json 3 reprise run --case <caseId> --allow-run --wait --json 4 reprise report --experiment <id> --json → data.reportPath 交给人看
MCP 第一版不做；若以后做，工具与这四条 1:1，不发明第三套名字。

#选项草稿倾向
1recover 是否拆 freeze + recover第一版合并；脚本要中间检查再拆
2非 TTY 是否默认 JSON是；人类管道用 --table
3run 是否马上支持候选 --product/--model标志预留；可先绑来源 Pack
4--wait 默认开还是关agent 文档建议开；默认关以免 TTY 人以为卡死
5是否暴露 events JSONL第一版不做；status + report 足够

Comparison 单独重跑（模型失败后）可以之后再加 reprise compare --experiment。第一版用 run --wait 的收尾路径，避免两个计费入口。
