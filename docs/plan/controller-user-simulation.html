要模拟的对象

在新候选会话的每个用户输入边界，写出这个人现在会输入的话，或判断他现在会结束。

给定：冻结历史会话；当前这条候选会话与隔离工作区。
求：send(message) 或 done(reason)。
约束：候选只看见本 run 已发出的用户句；历史只给 Controller；原文按需可读。

你的方案（按你的原话展开）

Controller 像普通 coding agent：固定说明 + 路径 + 自己去读文件，而不是每轮吞一份结构化试卷。

开场
  system prompt（角色、知情/开口规则、信封）
  + 历史会话材料的路径
  + 当前项目（隔离副本）的路径
  → 只允许 send → 第一句用户输入

之后每个候选回合结算
  再调 Controller（同一职责，固定决策 prompt）
  + 最新一轮候选过程与输出的路径
  + 仍能读到历史会话路径、项目路径
  → 自己读它认为需要的文件
  → send 下一句 或 done
  • 进入模型的默认文本只有 prompt 和路径（外加信封 schema），没有历史用户句全文，没有 finalMessage。
  • 读什么由 Controller 决定；Host 保证那些路径上的文件存在、完整、只读、可复原。
  • 当前项目路径用来约束：看产物、改口到这个工作区；不是把历史绝对路径交给候选。

客观分析

方向对。比继续给 SteeringContext 加字段更接近「模拟这个人怎么工作」。下面分成立条件、和现行能力的关系、以及方案本身的漏洞。

成立的部分

  • 知情和开口分开：历史在磁盘上，开口是信封里的一句。模型要引用后文必须先 read，成本高于直接从 JSON 复制。
  • 开场默认看不到后文全文，第一句只能从「去读历史」里自己取；prompt 可以规定开场只读任务句和交付前材料。
  • 每轮主输入是「这一轮发生了什么」的路径，停机判断被绑到当前候选，而不是绑到历史终态句。
  • 与 Recovery/Comparison 已有的工作区工具一致：read / ls / grep，而不是发明第三套分页 RPC。
  • Host 仍然只在结算后调用一次、只执行 send/done。你没有把写用户句的权力交回 Host。

和现在其实已经有的东西

read_observation(transcript | run_events) 已经是「去读原文」。失败不是没有读能力，是默认 JSON 已经把原文（用户句）和终态句喂饱了，工具变成可选。你的方案有效，当且仅当默认输入里删掉那些正文，只留路径。

必须补上、否则方案不成立

点若不做
历史材料和「最新一轮」文件不能放在隔离副本里 候选 cwd 就是副本。文件一进副本，候选可以自己读到历史会话，对照作废
路径指向的目录里要有目录文件（有哪些文件、哪条是最新一轮） 只给一个根路径，模型会 ls 乱翻或根本不翻
除「最新一轮」外，还要有「本 run 全部回合」的稳定路径 只给最新一轮，看不到候选上一句用户输入和更早产物变化；同一 Pi session 被压缩后更严重
开场仍要能定位冻结任务句（单独文件即可，不要整份 transcript 当开场必读） 第一句没有锚，模型会去读完整历史才能开题，后文再次泄漏进第一句
输出仍是校验过的 send/done JSON 自由文本无法驱动 CandidateRun

方案不会自动消灭的失败

  • 模型可以不读文件就 done。路径指针降低了「抄 JSON 后文」的概率，不提高「必须看产物」。缓解：决策 prompt 写明 done/satisfied 前应读本轮输出和当前项目里的交付文件；Host 仍不因零工具调用拒绝 done（与既有决策一致）。夹具抓假模型是否收到路径、是否在典型浅交付场景倾向 send。
  • 模型读了历史全文后仍可把 U3 当下一句原文发出。这要靠 prompt 的开口规则，不是路径机制能单独保证的。
  • 「启动 Controller」若理解成每轮新建 Pi session：每轮必须重读；行为更可复原，费用更高，也忘不掉「我已经纠正过页面空白」。若理解成同一 run 内复用 session：少重复读，但 compact 后磁盘文件仍是真相，prompt 应写「以磁盘文件为准，不以你记忆中的摘要为准」。

相对「继续做 JSON 试卷」的判断

你的方案是更好的默认形态。JSON 试卷适合 Host 审计 digest，不适合当模型的主输入。审计可以：指针消息全文 + 所列文件的 hash 写入 controller.requested。不要为了审计再把文件内容嵌回 prompt。

磁盘上放什么

两棵树。Controller 工具根 = 私有目录（可读历史与本 run 观察）。read 另挂只读副本，或 prompt 给出副本绝对路径且工具白名单允许读该根、禁止写用户源目录。候选进程 cwd 只有副本，看不见私有目录。

controller-briefing/                  Host 写入，Target 不可见
  INDEX.md                             路径清单（唯一建议放进 prompt 的「地图」）
  history/
    initial-input.txt                  冻结任务句
    transcript/                        按消息或按段的原文（用户/助手/工具）
    outline.tsv                        role, id, bytes, after_first_deliverable
  project-root.txt                     隔离副本绝对路径（约束用）
  run/
    sent-user-messages.jsonl           本 run 已发出的用户句
    turns/0001/                        第 1 个已结算候选回合
      visible.txt                      该轮对用户可见的助手文本
      events.jsonl                     该轮规范化事件（或摘录）
      changed-paths.txt                该轮后工作区改动路径
    turns/0002/                        最新一轮（结算后 Host 追加）
  THIS-TURN.txt                        仅一行：turns/0002 相对路径
  • 开场 prompt 指向：INDEX.md、history/initial-input.txt、project-root.txt。INDEX.md 全文同时贴进 append。不要把完整 transcript 列为开场必读。
  • 结算后 prompt 指向：INDEX.md、THIS-TURN.txt、project-root.txt。新 INDEX 全文再贴进该次 append。历史和更早 turns/ 按需读。
  • 这些文件由 Host 从 TaskCase 与 run 事件确定性生成，不经另一模型摘要。内容变化则更新 hash，供 requested digest。
  • Controller 只用工作区工具读 briefing 与 project/。不注册 read_observation。

循环

与现在同一条编排。变的是每次 decide 的用户消息：路径清单，不是 SteeringContext JSON 全文。

prepareRun（副本就绪）
→ 写 controller-briefing/（历史 + INDEX + 空 run/）
→ 拉起 Target；打开 Controller session
→ append(开场固定 prompt + 开场路径)
     → send → start(message)

每个 TurnSettlement：
→ 写入 turns/NNNN/ 与 THIS-TURN.txt
→ append(决策固定 prompt + 更新后的路径)
     → send → submit(message)
     → done → settleController(reason)
开场固定 prompt 要写清结算后固定 prompt 要写清
读 initial-input 和项目路径；需要口吻/约束可再读 history。禁止把交付后用户句写进第一句。必须 send。 先读 THIS-TURN 与项目里当前产物。历史用于判断这个人会不会停、会不会改，不按顺序发送。可以 send 或 done。

「启动」指 Host 在该输入边界对同一 Controller Pi session 再 append 一次，不是重启 Target，也不是每轮新建 Controller session。append 正文含 INDEX.md 全文。磁盘文件仍是 compact 之后的真相。

已定三项

路径指针方案采纳。下列选择已锁定，落地时写进 ADR 与 prompt，不在实现里改口径。

#决定含义
1 Pi session 全程一个 session 每个 CandidateRun 一个 Controller session。结算后对该 session append，不新建。prompt 写明以 briefing 目录文件为准，不以 compact 摘要为准。
2 INDEX INDEX.md 全文贴进每一次 append 地图进模型默认输入。transcript、turns 正文、助手实现不进 append。INDEX 更新后（新回合目录、THIS-TURN）下一轮 append 用新全文。
3 读文件与 done 仅 prompt 要求 决策 prompt 要求 done/satisfied 前阅读本轮输出与项目产物。Host 不因本轮零 read 拒绝 done，不记 controller failure。不校验「用完」历史用户句。

用户句和历史助手正文都不进 prompt；只在 Target 不可见的 briefing 目录以文件存在。大纲为 outline.tsv：role、id、bytes、交付边界布尔，不贴助手首行。baseline.finalMessage 不进 append。
