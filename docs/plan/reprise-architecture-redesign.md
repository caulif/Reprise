# Reprise 架构重构规划

状态：目标设计已由用户确认，供后续实施；本文不宣称代码已完成迁移，也不覆盖当前架构规范。

本文是本轮重构目标与验收的唯一文字来源。选择理由见[重构决策提案](../decisions/proposed/2026-09-07-reprise-session-harness-workflow.md)。当前实现依据仍为[架构总览](../architecture/overview.md)。

## 1. 产品边界

Reprise 在本机冻结历史任务、准备任务起点、运行候选 coding agent，并按需对照结果。Controller 模拟原用户的协作与停止习惯。实验不把历史答案泄露给候选，不把环境限制解释成模型能力差异。

用户入口按顺序为：配置内部模型、选择历史会话、选择 coding agent 及其模型、启动执行、查看结果路径、选择是否对照。配置可复用；三个内部角色共用一份模型配置，无角色级模型覆盖。每次实验记录实际使用的配置与依赖版本，凭据除外；运行期间不静默换模型。

CLI 与 TUI 功能对等，全部配置、发现、执行、取消、历史和对照操作都可以只通过 CLI 完成。CLI 同时提供完整 run 和 prepare → run --scenario → compare 分步路径，共用实现。新增 coding agent 通过显式配置的可信本地 Product Pack 接入，在现有插件契约范围内不修改宿主源码。

运行期间提供进度与取消，不提供指令追加、暂停续跑或模型切换。恢复证据不足时停止并解释原因，保存调查结果，不提供接受不足场景后继续的入口。对照可以在运行结束后发起，也可以从本机历史实验独立发起。

目标平台是 Windows、macOS、Linux，各自运行本机任务并查看本机历史。范围不包含跨系统重放、跨机历史迁移、远程运行、后台常驻服务、实验断点续跑、通用插件市场或独立发布的 Agent 框架。

## 2. 架构与所有权

这是单 package 的模块化单体，三种职责通过普通函数和对象组合；不建立通用 workflow engine、DI 容器或六层基础框架。目录组织服务所有权，不强制每种职责对应一个模块。

| 职责 | 拥有的内容 | 使用的能力 | 不拥有的内容 |
|---|---|---|---|
| Agent 执行机制 | Session、Invocation、消息上下文、loop、压缩、取消、输出格式处理 | Pi Agent、pi-ai、注入工具、记录接口 | 实验状态、恢复结果是否可用、候选投递、报告发布 |
| Reprise harness | 三角色行为、工具权限、场景准备、CandidateRun、业务检查与结果 | Agent 执行机制、Environment、Product Pack、存储 | TUI 导航、模型 provider 私有协议 |
| Workflow | 配置与选择后的调用顺序、取消传播、结果入口、独立对照 | harness 操作、本机历史查询 | Agent 工具循环、候选 turn 判断、工具内部文件操作 |
| TUI / CLI | 功能对等的操作入口；TUI 管导航，CLI 管参数、输出和退出码 | 同一 Workflow、配置服务、只读查询与活动事实 | 实验状态机、accept/resolve 等活业务句柄、产品专属策略 |

存储、平台 helper、Environment、Product Pack 是具体基础实现，不另设统一“能力层”。依赖方向为 TUI/CLI → Workflow → harness → Agent 执行机制；harness 同时直接使用环境、产品和存储。Agent 通过注入的工具与记录接口连接外部能力，不反向导入实验逻辑。

TUI 不启动 CLI 子进程执行业务，CLI 不导入 TUI 页面或模拟按键。配置、查询、规范化活动和错误分类由两种入口共同消费。插件注册表由启动装配处加载并注入；查询已保存历史无需执行插件代码。

源码落点以现有模块为起点：[Agent Host](../../src/infrastructure/pi-agent-host.ts)、[Pi 调用](../../src/infrastructure/pi-model-caller.ts)、[编排](../../src/application/experiment.ts)、[平台](../../src/infrastructure/platform.ts)、[产品进程](../../src/products/shared/process.ts)。先调整职责和实际调用链，目录搬迁仅在能让所有权更清楚时进行。

## 3. Agent 执行机制

### 3.1 核心对象

Session 是一个角色持续使用的对话，拥有稳定 ID、配置快照、消息历史和活动调用。Invocation 是 harness 发起的一次请求，包含零到多次模型请求、工具执行、压缩及输出修复。模型请求另有独立标识；候选 coding agent 的 turn 不等同于 Pi loop 的 turn。

单个 Session 同时只有一个活动 Invocation；不同实验创建独立 Session。运行中的消息上下文与持久化历史分离，压缩不删除历史。创建 Session、发起 Invocation、订阅事件、取消当前调用、关闭 Session 是主要操作；历史查询单独读取存储，不实例化模型或 Runtime。

### 3.2 能力及边界

| 能力 | 设计 |
|---|---|
| Agent loop | 直接复用 Pi Agent 的模型响应 → 工具执行 → 工具结果 → 后续响应循环 |
| 模型调用 | 通过 pi-ai provider 与模型目录；检查所选模型的输入、工具、推理参数与窗口能力 |
| 消息 | 保留文本、图片、工具调用、工具结果的结构；不把所有内容压平成字符串 |
| 工具注入 | harness 按角色提供实际工具，Pi 校验参数并调度；权限和副作用由工具实现控制 |
| 并发 | 独立读取可并行；写同一工作区或改变共享状态的工具串行；结果关联原调用 ID |
| 流式事件 | 保留调用、消息和工具的起止及增量；关联 experiment、session、invocation 与请求标识 |
| 上下文压缩 | 预留 system prompt、工具定义和输出空间；保留完整工具配对与最近上下文；记录 summary + retained tail 和触发原因 |
| 取消与关闭 | 取消传递到模型和工具；停止追加新调用，等待有界收尾；关闭释放会话资源；取消不回滚文件副作用 |
| 重试 | 明确唯一重试所有者，避免 provider 与 Host 重试叠乘；区分限流、网络、超限、非法输出与取消 |
| 结构化输出 | 按 Invocation 可选 schema；解析、校验和有限修复共用；业务合法性由 harness 判断 |
| 预算 | 请求超时、模型调用数、工具输出大小及上下文预算可控；修复、重试、压缩计入适用预算与用量 |
| 用量 | 记录实际模型身份、token、耗时、重试与压缩成本；未知费用显示 unavailable，不写成零 |
| 持久化 | 消息与关键执行事实按顺序保存；内容附件可引用；写入失败不能仍宣告调用成功 |

模型请求重试不重放已执行工具；发生部分输出、工具副作用或投递不确定时必须保留事实并按对应业务处理。恢复不了的上下文超限产生明确失败，不能静默删除关键消息。取消调用、provider 故障、输出格式错误和实验停止原因分别表达，不挤进同一个“失败”布尔值。

### 3.3 Pi 复用与外部参考

直接复用安装版本中确实可执行的 Agent、provider、事件、工具调度等能力。压缩和 Session/JSONL 存储以公开 API 及行为验证决定复用范围；不同时维护两套独立会话事实源。

调研基线为 Pi 0.84.1：Agent loop 可用；高级 AgentHarness 的 prompt、compact、resume 等在所检查版本仍有 HarnessNotImplemented 分支。类型声明不构成可用性证明。后续升级必须检查实际实现和验证证据，不能以未来 API 为前提设计必需路径。

缺口参考顺序为现有 helper、Node/Pi 可用实现、官方组件或高质量插件、最小本地实现。Agent 能力参考与 Product Pack 产品扩展分别处理：前者按具体功能选择复用，后者使用本文的显式启动加载契约。都需评估公开 API、测试、许可证、维护状况、Windows/macOS/Linux 支持与权限边界，不引入插件市场或热加载。

不建设会话分叉、历史回滚、运行中模型切换和人类 steer/followUp 入口。Pi 拥有这些能力不代表 Reprise 必须暴露它们。

## 4. 三个角色与业务检查

| 角色 | Session 范围 | 输入与权限 | 行为与输出 |
|---|---|---|---|
| Recovery | 一次场景准备一个 Session | 历史与取证材料只读；只写受控恢复副本 | 连续调查、修复、接受就绪反馈；证据足够且检查通过才封存场景 |
| Controller | 一次 CandidateRun 一个 Session | 历史、当前候选结果及证据只读；无修改候选或投递 Runtime 的权限 | 第一次请求理解历史并写开场；后续 send 或 done；模拟原用户 |
| Comparison | 一次对照 attempt 一个 Session | 历史、运行记录、候选结果只读；只写对照工作目录和报告 | 连续调查、规划、撰写、修订；返回报告及证据引用 |

三个角色共用模型配置，prompt、工具集合和业务函数在各角色旁维护，不另设 Agent Contract 架构层。每个角色可有若干 Invocation；单 Session 不等于单次模型调用。

Controller 不承担严格验收者或评分器职责。历史用户句是能力、约束与停止习惯的证据，不是逐条重发的脚本；历史 agent 的答案不是原用户先验知识。Controller 第一次请求可读完整历史并形成开场，不要求独立 Understanding 调用，也不强制维护 Host 账本。角色需要的工作笔记可以记录，不能成为伪装的客观验收证明。

Controller 是实验条件的一部分：记录提示词和协作策略版本、可见材料、压缩策略、干预消息与用量。相同模型配置不保证相同协作轨迹；独立候选使用独立 Session，不读取其他候选轨迹。报告区分实际 Agent 配置差异与模型差异，不把一次历史对照解释成模型因果效应。

完成判断由 Controller 根据当前证据作出。“读过一个文件”“账本为空”“报告存在”都不能证明任务成功。harness 只机械校验输出格式、opening 必须 send、消息边界和引用归属等明确条件，不用统一阈值替代用户语义。

业务检查跟随所有者：Recovery 检查起点证据、就绪条件和源目录保护；运行检查投递与 settlement；Comparison 检查报告存在、证据归属和发布条件。可修复问题在原 Session 有界反馈；证据不足、源目录变化、预算耗尽或权限不足停止。上一份格式合法结果只有在对应环境版本仍匹配且业务允许时才可参考，不是通用“保留旧信封即成功”。

Workbench 对应 harness 的工具与环境配置，Brief 对应各角色准备输入的函数，Verifier 对应业务检查，Audit 对应事件记录接入。它们的职责保留，但不作为四个通用内核子系统；输入可使用直接消息、结构化内容或文件引用，不强制所有输入写成 brief.md + INDEX.md。

## 5. Workflow 与状态

### 5.1 正常运行

1. 读取内部模型配置；用户选择历史会话、候选 coding agent 和模型。
2. 预检查本机工具、所需权限和模型能力；有费用的模型检查遵守显式运行准入。
3. 导入并冻结 TaskCase；记录来源、本机路径及可用历史。冻结是普通操作，不需要独立状态机。
4. 在副本中准备场景；机械证据足够时直接检查，否则调用 Recovery。证据不足则保存原因并停止。
5. 场景可用后创建独立候选副本，提交运行尝试记录，装配 Product Pack 和 Controller Session。
6. Controller 第一次 Invocation 读取历史并形成开场；Host 先记录决定，再投递候选。
7. 候选 turn 达到公开 settlement 边界后，Host 记录本轮事实；Controller 在同一 Session 决定 send 或 done。
8. 收尾停止候选、核验目录、保存结果与清理状态，释放会话，展示结果路径。
9. 用户选择直接查看产物或发起对照；对照读取已保存输入，创建独立 attempt 和 Comparison Session。

对照不挂在运行函数尾部等待 Promise。普通 await 可以串联自动阶段；持久化产物支持历史查看和独立对照，不意味着每个步骤都必须可重入、幂等续跑。

场景准备封存后，执行只从指定场景版本创建副本，不回到历史源目录猜起点或补删文件。执行所需材料已经保存，移走原始会话及来源目录不改变场景；仍需当前本机 Runtime 与声明的外部依赖。相同场景的每次 run 创建新 runId 和独立副本，初始指纹一致。分步执行是重新启动一次操作，不是恢复旧实验的副作用。

### 5.2 状态归属

Agent 执行机制管理活动 Invocation 与关闭状态；CandidateRun 在 harness 内拥有准备、启动、等待候选、等待 Controller、收尾和完成的状态转换。沿用 assertTransition 的唯一转移入口，迁移时一起调整其所有权与引用。状态机跟随业务，不位于所有模块共享的最低层。

Recovery 用一个所有者集中管理调查与检查结果，只有真实生命周期分支要求时才使用显式状态机；不要求每阶段都建转移表。顺序冻结和对照使用普通函数及明确结果。

保留 accepted ≠ started ≠ settled；投递 unknown 不自动重发。普通输出不是 turn 完成信号。先记录投递意图并不能保证外部操作恰好一次，崩溃窗口内保持未知而非猜测。

### 5.3 停止路径

| 情况 | 行为 |
|---|---|
| 恢复证据不足 | 保存调查、缺口和解释；停止，不创建可执行场景，不提供强行接受入口 |
| 用户取消 | 传递取消至活动 Session 和 Runtime；有界清理，保存取消与残留资源事实 |
| 正常退出程序 | 走取消和清理，再结束；不默认托管后台任务 |
| 进程崩溃 | 重开时展示未闭合操作为中断/未知；不自动恢复或重发，不假定子进程已消失 |
| 预算达到 | 以 limit 结束，保留已有事实，不包装成任务完成 |
| 对照失败 | 保留失败 attempt；不修改 RunOutcome，不覆盖旧的成功报告 |

任务判断、终止原因与清理结果保持正交。证据不足属于场景准备结果，不伪造候选已执行的 RunOutcome。

### 5.4 CLI 与 TUI 对等操作

以下是目标命令职责，实际参数名及公共响应 schema 在实施时一起确定；业务动作不能只有 TUI 入口。无参数且有 TTY 时进入 TUI，无 TTY 时显示帮助或要求子命令，不尝试启动全屏界面。界面的焦点、折叠和页面导航不映射成业务命令。

| 操作 | CLI 目标入口 | 共同应用行为 |
|---|---|---|
| 内部模型与认证 | config show / set / validate；auth status / login / logout | 配置同一内部模型；API key 隐藏输入或标准输入；受 provider 支持的 OAuth 可打开浏览器或使用设备流程，无需 TUI |
| 产品插件 | products list / inspect；plugins list / add / remove | 查看能力、兼容性及诊断；add/remove 只更新显式加载配置，不下载、不安装、不热加载 |
| 模型与历史来源 | models list --product；sessions list / show | 模型来自候选 Pack；会话分页带稳定产品身份、源路径和不透明 cursor |
| 预检查 | preflight | 检查配置、平台、运行能力；不以“检查”为由隐式产生模型费用 |
| 完整运行 | run --source-product … --session … --candidate-product … --model … | 调用同一 prepare 与 runScenario 实现，停在候选结果；不自动对照 |
| 分步执行 | prepare --source-product … --session …；run --scenario … --candidate-product … --model … | prepare 输出 scenarioId；run 校验场景完整性并启动新候选，不能绕过就绪检查 |
| 状态与历史 | experiments list / show；events --experiment … | 查询当前或终态投影；事件支持按 cursor 分页或跟随，不创建模型或 Runtime |
| 取消 | cancel <id>；Ctrl+C | 取消 prepare、候选 run 或对照操作；另一终端可以取消 CLI/TUI 所有者正在执行的工作 |
| 对照与产物 | compare <runId>；artifacts list；report show / open | 独立生成对照；读取报告、原始产物和 Session 附件；无桌面也能得到结果路径 |

来源身份使用 productId + sessionId，存在歧义时使用列表返回的 sourcePath，不能只凭标题或列表序号。来源产品负责历史导入和恢复知识，候选产品负责执行与模型解析，两者可不同，不用一个含混的 --product 同时表示二者。场景输入与来源会话输入互斥，缺失或冲突在副作用前报错。

run、prepare、compare 默认前台运行到结果落盘与有界收尾完成，不提供立即返回却没有执行所有者的后台模式。最初的活动记录在首次可能耗时的模型调用之前发布，返回或流出 experimentId 与具体 operationId，供另一终端查看和取消。对一个场景再次 run 是新尝试，不复用旧 runId。

CLI 的 --json 输出单个版本化结果对象，stdout 不混入日志；进度及诊断写 stderr。显式 --jsonl 输出版本化事件流，首条带活动标识，正常结束有最终结果记录；它与 --json 互斥。不依赖 TTY 猜测稳定机器协议，脚本明确选择输出模式。流因进程崩溃未闭合时，调用方查询已保存状态，不能根据 EOF 推断成功。事件可按序号继续读取，但不包含控制端点凭据。

响应分别表示命令是否执行成功和业务结果：查询一个失败实验可以成功退出；prepare 因证据不足或 run 因协议故障结束，返回明确错误分类和非零退出码；正常运行得到任务未完成判断时，用业务结果表达，不冒充 CLI 执行异常。用法、未找到、能力不足、锁冲突、取消、等待超时等退出码映射在 CLI 契约中固定；人类文案变化不影响稳定 error kind。CLI JSON 读写按 schema 校验。

配置更新校验后原子写入，多个入口更新同一配置需串行化，活动实验使用启动时快照；config show、错误和事件不回显秘密。账号入口管理的是 Reprise 内部模型服务，候选产品仍自行管理账号和全局配置。付费操作沿用显式 opt-in 准入，不把纯读取或预检查变成付费探测，也不额外增加无关确认步骤。

### 5.5 跨终端取消与单写者

取消发送者是命令客户端，活动 CLI/TUI 进程仍是实验唯一写者。每个活动所有者提供随进程生灭的本机控制端点：Windows 命名管道，macOS/Linux 使用私有目录内 Unix domain socket。端点元数据存放于同一 dataDir 的受保护控制目录，包含所有者实例标识与支持的控制协议版本；路径长度按平台处理。不监听公网，不增加常驻服务。

cancel <id> 接受具体 prepare/run/comparison 操作 ID，也可接受 experimentId。实验 ID 在发请求时解析并绑定具体活动操作与所有者实例，不能在等待期间自动转向后启动的对照或下一次 run；存在多个活动目标时要求明确 operationId，不能随机取消。独立 prepare 同样有活动标识并出现在列表中。

控制目录权限限制为当前用户；消息校验长度、版本和目标 ID。端点使用每次所有者启动的新实例标识及本地认证材料绑定请求，认证材料不进入事件、CLI 输出或模型上下文。命名管道等端点无法满足本机权限要求时明确失败，不能回退到未鉴权 TCP。

接收者确认目标仍属于本实例、记录取消请求，再触发同一 AbortSignal 收尾路径。Ctrl+C 与跨终端请求汇入该路径。重复请求幂等；已结束返回 already_finished，不修改原终态；accepted 只表示取消已接收，不能等同于进程已终止或清理成功。cancel 默认等待有界时间确认目标终态，超时返回非零状态并带已观察的接收结果和操作 ID；后续用 experiments show / events 查询，不能伪报完成。

所有者无响应、管道消失、PID 被复用或记录过期时返回不可达/未知，不删除 writer.lock、不按旧 PID 杀进程、不创建新写者“代为完成取消”。真正的后代进程清理由活动所有者或明确的后续残留处理负责；不在本命令中实现崩溃恢复。请求到达时原操作自然结束，返回实际终态，不强行改为 cancelled。

同一实验只允许一个写者；只读 CLI/TUI 可以查看已提交事实。不同实验各自锁定，共享配置另行串行化，不用 dataDir 全局运行锁阻止独立实验。新对照不能与同一实验的另一个写操作争用；返回锁冲突而非抢占。测试据此可从父进程启动 CLI、等待活动 ID、读取事件并通过另一进程取消。

## 6. 本机记录、Schema 与全过程查看

实验是用户浏览入口，关联冻结任务、场景准备、候选运行、三个角色的 Session 及对照 attempt。Session 历史不能代替候选原生事件、环境准备和实验结果。

| 数据 | 所有者与记录原则 |
|---|---|
| TaskCase / 场景结果 / RunRecord / 对照记录 | schema 跟随业务所有者；跨模块消费通过稳定导出，不由通用 Agent 内核认识全部产物 |
| Session 历史 | 完整输入输出和工具结果的唯一权威记录；实验事件引用消息或附件 ID，不复制第二套全文 |
| 模型请求 | 保存 system prompt、工具定义、实际可见消息与附件引用、模型参数；压缩后可复原 summary + retained tail |
| 运行与环境事实 | 实验记录持有；候选事件保留规范化事实及必要原始来源 |
| 流式展示 | 增量可以合并落盘；最终内容权威。中断的部分内容保留且标明不完整，不要求逐 token 动画回放 |

全过程包括角色输入输出、工具参数和结果、错误、重试、压缩、候选交互、产物和结束原因。大内容存附件，摘要与 digest 不能替代可读内容；模型实际只收到截断结果时，同时记录截断事实。只展示服务公开的推理内容，不推测隐藏推理。

凭据必须在进入日志和模型可见工具输出之前过滤或阻止；认证由独立凭据通道管理。不保存 API key、Bearer、Codex CLI 凭据或未经筛选的环境变量。存在脱敏时明确记录遮蔽事实，不能承诺重建原始秘密。

存储复用现有单写者、顺序追加与附件机制。关键消息在依赖它的执行之前完成持久化；成功结果在必要记录完成后发布。写入失败停止依赖步骤；JSONL 尾部不完整与中部损坏区别处理，不静默忽略任意损坏。不可变结果原子发布，快照和索引可重建，不能作为第二事实源。

Value.Check 保留在持久化读写、模型输出、外部 JSON 边界；模块内可信类型不重复检查。目标是按所有权组织 schema 并让存储接受调用方 schema，实施时同步调整当前集中 schema 规则和导入门禁。

历史查看不需要 API 凭据、网络请求或运行中的对象。本机绝对路径可保留来源事实，产物引用使用 ID 或实验内相对路径；没有跨机迁移格式承诺。目录被用户删除时显示缺失，不重建虚假的证据。

候选结束时封存对照所需的终态文件快照、内容指纹和原始事件引用。对照读取封存快照或受控只读视图，不以用户后来可编辑的工作目录替代终态证据；快照范围、排除项和缺失内容如实记录。派生检查和媒体转换另存来源与输出，不能改写封存事实。数据目录的外部篡改不靠“只读”称谓解决，读取关键证据时检查完整性。

插件在运行时产出的规范化活动、最终事实和产品展示元数据一并持久化。移除或升级 Pack 后仍能读取旧实验及生成基于封存证据的对照；重新导入来源或启动候选才依赖兼容插件。原生未知字段可保存在带命名空间的附件中，不能要求历史查看时重新运行插件翻译器。

## 7. Windows、macOS、Linux

三平台共用 Agent、harness 和 workflow。平台分支集中在已有 helper 与 Product Pack，业务代码不按操作系统分叉。

| 边界 | Windows | macOS / Linux | 共同要求 |
|---|---|---|---|
| Shell | PowerShell，明确版本及 UTF-8 行为 | Bash，启动前检查可用性 | 无交互 profile；版本与 Shell 类型进入模型上下文及记录；缺失时停止并给修复指引 |
| 程序启动 | 原生可执行文件；.cmd/.bat 专门 argv 适配 | 原生 executable + args | 程序调用不用 shell:true；任意 Shell 脚本走明确的 Shell 工具 |
| 进程清理 | 协作停止后清理进程树 | 协作停止后清理受管进程组 | 有界等待与强制终止；退出状态和残留资源可观察，不能只杀父进程 |
| 路径和文件 | 本机盘符、保留名、长路径、junction | 本机路径、执行位、symlink | Node 路径 API；检查实际文件系统大小写及链接行为，不能统一转小写 |
| 保存结果 | 处理文件占用与 rename 失败 | 保留所需权限并原子发布 | 保留字节与必要元数据，不自动变换 CRLF/LF；失败不覆盖成功产物 |
| 打开结果 | 系统文件管理器 | open / xdg-open，按可用性调用 | 无桌面时显示路径；打开失败不改变实验结果 |
| TUI | 本机终端 | 本机终端 | 复用 Pi TUI；验证中文、缩放、退出恢复；无 TTY 使用可读结果输出 |

不要求 Windows 安装 Git Bash，不把 WSL 作为 Windows 必经依赖；若在 WSL 中运行，它属于 Linux 环境，不能自动混用 Windows CLI 和路径。三个系统各跑本机历史，因此无需翻译异系统历史路径或提供跨机查看。

预检查探测实际 executable、Shell、目录权限与所需隔离能力，不从 PATH 字符串猜测 Git 是否存在。复制必须处理目录外链接、大小写冲突、执行权限及不能保留的文件类型；影响任务可运行性时停止并解释，不能悄悄改写场景。

工作目录副本与 tripwire 是环境保护措施，不是任意 Shell 的安全沙箱。工具路径检查不能限制 Shell 的所有副作用。harness 声明本次运行需要的读写和网络权限；执行环境与 Product Pack 验证可满足这些要求，能力不足则预检查停止，不静默升级权限。原生隔离组件的具体复用方案须以三平台验证选定，不复制三套 Codex 沙箱实现作为前置承诺。

支持目标不等于验证结论。支持矩阵记录实际验证的 OS 版本、CPU 架构、Node、Shell、候选 CLI 版本；未测试组合不标正式支持。三平台 CI 验证构建、相关测试和模拟 Runtime 流程，真实调用保持显式 opt-in。

## 8. 可扩展 Product Pack

### 8.1 加载与版本

Product Pack 承担产品私有协议适配，不承担实验策略或 UI。插件来源是用户显式配置的本地 JavaScript 入口、TypeScript 编译产物或已安装包，启动时解析并加载；不运行原始 .ts、不在线下载依赖、不扫描任意目录、不热加载、不建设插件市场。配置中的相对路径以配置文件目录为基准，包解析位置明确且稳定，不随 shell 的当前目录变化。

每个插件带可在执行入口前读取的 manifest，说明稳定 productId、显示名、Pack 版本、宿主插件 API 版本、入口及能力声明。宿主校验来源和 manifest 后加载模块、校验导出，生成只读注册表；重复 productId 或不兼容 API 显式拒绝，不能按加载顺序覆盖内置插件。插件异常作为该插件诊断显示，其他可用产品仍可使用；选中失败插件的操作停止。首版将插件当作可信进程内代码，这不提供隔离同步死循环或恶意代码的保证。

Codex、Claude 及外部插件都通过同一套公共契约注册。核心程序禁止深层导入具体 Pack；插件禁止深层导入宿主应用、TUI 或存储实现。API major 不兼容拒绝加载，兼容扩展采用可选能力和默认缺省行为。版本范围仅表示插件 API 兼容，不证明任意产品 CLI 版本都适配。

插件不得在导入时启动候选、调用付费模型或改用户配置。实际探测与运行在显式操作中完成。运行记录保存 Pack/API 版本、manifest 与实际入口内容标识、可观察 Runtime 版本/模型/配置及本次能力探测结果；会话中的秘密不进入指纹。已启动所有者不重新加载插件，变更在下一次命令或 TUI 启动生效。

### 8.2 插件与宿主的契约

| 插件侧能力 | 宿主责任 |
|---|---|
| manifest 与配置 schema | 通用插件配置、版本验证、注册与错误显示；插件配置读写由宿主管理 |
| sessions：discover / inspect / import | 稳定身份、冻结、隐私与持久化；Pack 只返回规范化 ImportedSession |
| runtime：可用性、候选模型目录与验证、runner | 通用产品选择和预检查、CandidateRun 生命周期、预算、取消及收尾 |
| runner：start / send / waitForTurn / inspect / stop | 接受与 settlement 分离、不确定输入不重发、结果与清理正交 |
| 原生事件与错误的规范化、活动和运行事实 | CLI/TUI/报告共用的展示数据；宿主拥有文案和布局，无产品专属分支 |
| 恢复知识与证据来源 | Recovery 策略和场景检查；知识不能授予权限、执行脚本或放宽停止条件 |
| 认证状态与安装指引 | 只显示可观察状态；不读 Codex CLI 凭据，不代为安装 Runtime 或修改其全局配置 |

会话导入与候选运行是独立可选能力：导入型 Pack 可提供历史而无可执行 Runtime，运行型 Pack 可执行其他来源场景而无历史导入。界面按能力显示合法操作，无能力时给明确原因，不以空列表或虚构模型目录冒充成功。原生 admission、settlement、用量、取消和终止确认能力声明必须由本机探测与观测佐证；不足时按统一准入规则停止或记录已允许的不确定性。

模型目录来自所选候选 Pack，不能从 pi-ai 目录猜测。来源 Pack 与候选 Pack 分离，插件不能修改 Controller/Comparison 的产品专属策略，不能自行接受恢复结果、调整实验状态或放宽权限。未知活动使用稳定通用类别与命名空间数据；新增产品的常规活动不要求修改核心枚举。

### 8.3 接入验收

发布面是窄的版本化契约与共享契约测试，不是宿主全部源码。用一个独立测试插件作为第三产品：只新增插件包与配置，在宿主源码不变时出现在 CLI/TUI、列出模型、导入 fixture、执行模拟 Runtime 并产生可查看结果。内置两 Pack 跑同一套用例。

契约测试覆盖重复 ID、版本不匹配、无能力、非法返回、未知事件、分页与身份、投递 unknown、不重复输入、取消及清理、凭据遮蔽、移除插件后的旧记录查看。测试可使用模拟 Runtime，默认不产生外部费用；特定产品真实 smoke 仍显式 opt-in。

“新增产品不改宿主”限定在现有 API 支持的能力内；真正新增业务能力需要版本化演进契约，不用任意回调绕过边界。三平台支持按各 Pack 实际验证组合报告，不要求仅支持 Linux 的产品伪装可在 Windows 运行。

## 9. 迁移计划

按下面可验证的顺序实施；每一步先形成独立工作任务，提供最小有效 diff。回退依赖代码版本与版本化新记录，不覆盖已有实验数据，不默认提交或 push。

| 批次 | 工作边界 | 完成证据 |
|---|---|---|
| M1 | 验证 Pi 公开 API、Session/JSONL 与压缩复用范围，确定唯一记录所有者 | 模拟 provider 下多轮工具对话、保存重开、压缩及取消的可运行检查；确认不依赖占位 API |
| M2 | 收薄共用 Session Host，保留结构化消息和输出处理，统一预算与事件接入 | 完整模型输入可重建；同 Session 多轮连续；非法输出、重试与取消不会伪造成功或重放工具 |
| M3 | 收拢三角色：连续 Recovery、用户模拟 Controller、单会话 Comparison | 无独立 Understanding 和双会话对照要求；不足场景停止；反馈保持上下文 |
| M4 | 收拢 harness 所有权，移出 TUI 活句柄，建立对等 CLI 与完整/分步命令 | 同一 fixture 走两种入口结果语义一致；prepare 与 run --scenario 共用完整 run 实现；对照独立 |
| M5 | 本机实验历史完整投影、封存快照，明确 schema 归属与旧格式读取策略 | 无凭据无网络且无原 Pack 查看全过程；修改工作目录不改变对照输入；压缩前历史存在 |
| M6 | 平台 helper、进程树、文件语义、权限能力与三平台 CI | 三个平台执行共同检查及平台用例；不足能力明确停止；只有已验证组合进入支持矩阵 |
| M7 | 本机控制端点与跨终端取消，保留每实验单写者 | 另一个 CLI 取消 CLI/TUI 的 prepare/run/compare；重复、终态竞态、过期实例和不可达不误杀、不抢锁 |
| M8 | 版本化 Product Pack 契约、显式加载和公共展示事实，迁移内置 Pack | 独立第三插件只改包及配置完成接入；产品能力不足可诊断，移除插件仍读历史 |
| M9 | 同步当前规范与受影响决策，删除迁移兼容代码 | 文档、prompt、调用链一致；相关门禁通过；无两套同功能 Agent Host、CLI 编排或事实源 |

平台约束从 M1 起约束实现，M6 完成支持验证，不在最后才补 Windows 或 Unix 分支。新增 on-disk 格式使用显式版本；历史读取优先保留现有格式兼容，不能解析的版本明确报错，不自动重写旧记录。

实施时同步处理的当前约束包括：独立 Controller Understanding、Comparison 双会话、Controller 完成证据账本守卫、恢复人工接受路径、集中 schema / 状态机、Windows 唯一验证平台、静态 Product Pack 注册及 TUI 专属活动词汇。旧无头 CLI 方案中的对照自动挂尾、无所有者后台运行和不足场景继续不采用。它们的当前规范与 accepted 决策在对应代码批次生效时一起调整；本规划不提前宣布旧约束已失效。

| A12 | 当前规范、决策与实现同步；代码变更先 build 后运行 dist 测试及 npm run check；纯文档运行 npm run verify:docs |
| A13 | 只用 CLI 可完成全部 TUI 业务操作；完整 run 与 prepare → run --scenario → compare 使用同一应用实现；纯 CLI 路径不加载 TUI |
| A14 | --json 单一结果、--jsonl 有版本和结束记录，stderr 不污染 stdout；错误 kind 与退出码稳定；配置不回显凭据，活动 ID 在耗时工作前可见 |
| A15 | 同 dataDir 的第二进程可取消 CLI 或 TUI 的 prepare/run/compare；已接收与已完成可区分；重复取消、自然结束、断连和过期所有者不误改终态或误杀 PID |
| A16 | 独立测试 Pack 只增加本地包与显式配置即在 CLI/TUI 接入，宿主源码不变；API 不兼容和重复身份拒绝，导入型/运行型能力独立展示 |
| A17 | 冻结后移走历史来源仍可从场景执行；修改候选工作目录不改变封存对照输入；移除 Pack 后仍可读旧实验与已保存报告 |
| A18 | 插件共用契约检查 admission、settlement、错误、取消、清理和遮蔽；声明与实际能力分别记录，三平台按实测支持组合准入 |

实际 Controller 行为还需固定历史样例的人工语义评估，机械检查只证明调用与边界，不声称证明“像原用户”。真实 Runtime 验证依照[smoke 准入](../codex-smoke-gate.md)，不在默认门禁中产生外部费用。新增或修改工程门禁同批附反向用例，不降低覆盖率阈值。
