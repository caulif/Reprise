# TUI 界面重构实施计划

本文只写**怎么改现有界面**，不改写交互语义。目标行为以[TUI 阅读与交互规划](./reprise-tui-design.md)为准；本机 HTML 预览只演示页面与按键，不拥有设计事实，不能当终端证据。落地操作以[产品 TUI](../product/tui.md)为准。架构、CLI、Pack 契约不在本计划重做。

进度仍记在 [MASTER](../progress/MASTER.md)。开始本计划第一批时，把 MASTER 当前批次改成本文对应节；未开工前不把界面重构标成进行中。

## 完成判据

全部批次结束后，用户从首页斜杠进入、选来源、看恢复、选候选、读协作、看结果、可选对照、重开历史，走的是**同一条实验记录**；页面图、页脚键和阅读规则与目标规划一致。假终端帧审计通过；真终端 IME/滚轮/拖选仍按目标规划的宿主矩阵单独关闭，不并入某一视觉批次。

## 不做

- 不重写 `application/` 实验生命周期，不把状态机搬进 TUI。
- 不按 `productId` 分支页面，不嵌入产品原生 ANSI。
- 不新增聊天输入框、第二窗口、detach、假进度百分比。
- 不把 HTML 预览外侧导航、演示「完成阶段」按钮做成产品功能。
- 不把 `intake-tui.ts` 整文件推倒重来；按投影与输入分批替换。
- 不在本计划关闭付费模型 lane 或 Runtime smoke。

## 约束

- 依赖方向：`tui` → `application`。业务操作继续走现有 Workflow。
- 时间线只投影已持久化公开活动，折叠只改视图。
- 密钥不进画面明文、事件、artifact。
- 改渲染后必须重生成并提交 `docs/tui-audit/frames/`。
- 快捷键、页图、对照入口变化时，同批更新 `product/tui.md` 与相关 accepted ADR（阅读/选择已有记录则补影响，不另造平行决策）。

## 代码入口

界面所有者在 [`src/tui/`](../../src/tui/)。页图枚举在 [`workbench.ts`](../../src/tui/workbench.ts) 的 `WorkbenchPage`；输入在 [`controller-input.ts`](../../src/tui/controller-input.ts)；投影在 [`view-projection.ts`](../../src/tui/view-projection.ts)。列表与核对应 [`pages/intake.ts`](../../src/tui/pages/intake.ts)；连续记录在 [`pages/run.ts`](../../src/tui/pages/run.ts)、[`timeline.ts`](../../src/tui/timeline.ts)、[`fold-process.ts`](../../src/tui/fold-process.ts)、[`timeline-read.ts`](../../src/tui/timeline-read.ts)。

## 差距与改法

下面每行是实施意图，不是当前产品已经具备的能力。

### 1. 首页与命令

首页现在同时承担「继续最近实验 / 已冻结核 / `/run` `/find` `/home`」和斜杠浏览。目标首页只回答：新实验、历史、内部模型、界面语言；输入只接收应用命令。

改法：封面保留 `/intake`、`/history`、`/config`、`/lang`、`/help`。`/lang` 切换 TUI 中/英，继续作为操作者界面偏好，不决定报告或任务语言。查找只在实验记录里用 `/`。去掉封面 `/run` 作为主入口——选完来源并核对后才进入恢复。最近实验用一行摘要，Enter 打开该实验记录末尾，不另起「继续跑」语义。

### 2. 来源四层

产品 → 项目 → 会话 → 起点核对已经存在。缺口在信息层次：项目页右侧详情、筛选后空列表禁止确认、返回保留光标与筛选、空列表区分「无历史 / 无匹配 / 读取失败」。另有手填 `source` 根目录页，不在目标主路径。

改法：项目页宽屏左列表右详情（已有分栏则收成目标信息：名、会话数、最近活动、完整路径、最近任务）；窄屏上列表下详情。会话 Enter 只进核对，核对 Enter 才准备。删除或降级手填 `source` 页，使其不能从首页命令到达。发现、分页、排除计数的现有语义保留，只改展示位置与文案密度。

### 3. 内部模型

字段列表、单字段编辑、Ctrl+S、未保存离开确认已按选择 ADR 落地。缺口主要是封面文案把内部模型与候选模型缠在一起，以及配置失败原因是否够明确。

改法：配置页标题与说明固定为三个内部角色共用；候选目录不出现。失败保留草稿与原因，不显示密钥。目录可列举时用可筛选列表，自定义允许键入。

### 4. 一条连续记录

现在恢复、候选、对照门、结果是**换页**。对照门挡住时间线；结果页替换画布；历史详情是卡片不是记录。运行页还有左右栏、来源过滤、角色 overlay、恢复阶段也可能露出轮次。

改法：`running` 成为实验的唯一阅读面。恢复、候选协作、执行结束、对照过程与结论按事件顺序追加，用分段标题而不是清屏。候选产品 / 模型 / 确认是记录末尾的分层选择（可仍用独立 `WorkbenchPage`，但顶栏任务与已写下的恢复内容保持可见或可向上滚回）。取消对照门作为必经页：候选结束后停在记录末尾的结果段，`c` 才追加对照。顶栏只放任务、阶段、产品与模型、状态、耗时。默认单列；用 Tab/Enter 展开，不用第二栏当主阅读。角色 overlay 退出主路径；原始事件留在深层 viewer。

### 5. 结果、失败、中断

结果页目前是独立面板，键位 `o/t/w`，对照跳过写在卡片上。目标要同时看见模拟用户任务判断、技术终止、清理，以及可复制本地路径。

改法：结果段叠在同一画布底部。路径走已有 OSC 8 规则。历史打开实验时加载同一投影并定位最后结果。恢复不足、取消中 / 已取消、端点不可达、清理失败用各自文案，重开只读。

### 6. 视觉与页脚

当前 panel、pill、双密度、多套页脚键。目标是低彩度正文、一种强调色、底栏只列本页会响应的键。

改法：收敛 [`theme.ts`](../../src/tui/theme.ts) 与 [`widgets.ts`](../../src/tui/widgets.ts) 的框线；窄屏换行优先于整行截断。每页 `*Hints` 与目标规划对齐后，删掉无效键。`?` 仍打开本页说明。

## 批次

每批可审查、可 `npm run check`。不要并行改页图和主题到无法回滚。

| 批次 | 出口 | 主要改动 | 验证 |
|---|---|---|---|
| U1 页图 | 封面命令与实验阅读面分离 | 斜杠目录（含 `/lang`）；历史 Enter 进记录末尾；对照改为结果段 `c`；运行中 Esc 不取消 | `page-input`、`intake-ui`、`codex-intake-commands`；更新封面/结果/对照门帧 |
| U2 来源层 | 四层选择可返回且空匹配不能确认 | 项目页布局与详情；去掉主路径 `source`；空态三类文案 | `product-first-intake`、会话帧（含 CJK） |
| U3 记录面 | 恢复与候选同画布 | 分段标题；顶栏字段；候选选择叠在记录尾；去掉默认双栏与主路径过滤/角色层 | `timeline`、`widgets`、运行帧 |
| U4 终态 | 判断 / 终止 / 清理 / 路径可同时读 | 结果段与失败/中断投影；历史重开无副作用 | `local-history`、`tui-workflow`、结果帧 |
| U5 视觉 | 页脚与主题符合目标层次 | theme/widgets/i18n；配置页说明 | 全套 `tui-audit` 重录 |
| U6 规范 | 当前规范与目标对齐 | `product/tui.md` 改为落地行为；迁移表 TUI 行只留真终端缺口 | `npm run verify:docs` |

U1 必须先于 U3：先去掉对照门换页，再改画布结构，避免两套结果入口。U2 可与 U1 前后相邻，但不要和 U5 抢同一批帧。

## 风险

- 历史「用例 / 实验」双 Tab：目标首页不展示冻结核库。U1 把实验打开变成连续记录；用例复用留在历史次入口，直到产品决定删除该能力。
- `compare-gate` 与 CLI 默认不挂对照一致，只改 TUI 呈现位置，不改「对照单独启动」。
- 帧审计会大面积变。每批只更新该批触及的帧，禁止无关快照一起重录。
- 真终端矩阵（Windows Terminal/PowerShell、macOS Terminal/Bash、Linux 选定终端）仍是目标规划验收，U1–U5 用假 TUI 与 Windows 已有探针，不宣称三 OS 关闭。
